# 2026-10-28 新标定实物采集：132与160深度下限排查

用户同意三型号依次放到同一固定底座，先采132，再换160。两型原始RGB-D已保存。160接线盒完整位于彩图内，但盒口中心光轴深度约387.78mm，低于当前400mm采集下限。只把相机端深度下限暂改350mm后，完整外框恢复且视觉定位通过；随后已恢复400–800mm设置。本轮没有移动相机、修改手眼标定或下发机器人动作。100尚待就位采集。

用户确认132就位。初次网页预览与任务状态仍为10月22日160缓存，未将其当作新数据。实时右臂当时为上电拖动，用户按提示退出并下电后，三部件新鲜反馈均为off／manual／idle。相机起初仍由手眼HMI持有，检测服务打开设备返回`0x8006000e`；经现有`/inspection/camera/release`接口交给检测，WorkingMode=4恢复。

132任务`20261028_152656_ad8079`成功，采集过程状态监控有效，绑定活动标定SHA `76d7613ccb761512b1609e86e53b7269cac3b2cce97c971d6a82c70c2331bd41`。该帧盒口中心相机坐标约[-43.628,1.141,473.739]mm，平面RMSE0.1685mm。

网页成功帧的graded模式只保存摘要和标注图，因此另用原有相机CLI的full模式补存同一次完整帧的RGB、原始深度、内参和算法结果，形成独立记录，未混称同一帧。补存帧目录`JL132/full-evidence/frames/jl132/20261028_152858_652/`，其前后腰反馈最大差约0.000091°。本机保留`registered-camera-observation.json`：仅用该完整帧的camera_T_box与新标定固定世界相机变换计算世界位姿，不采用单独CLI中引用旧参考姿态得到的base_T_box。

132实测盒口中心比此前共同工位设计位置约前后差42.56mm、高差24.60mm；这进一步说明旧研究工位配置不能直接部署到本次实物摆放。

## 160原图与深度范围

用户确认160就位后，实时复核三部件停稳下电，保存完整原始帧`JM160/full-evidence/frames/jl160/20261028_153106_262/`。后续网页任务`20261028_153120_7cfda8`的状态监控有效，但外框定位失败。用户提出“可能接线盒不在视野内”，据此检查以下同场景对照。

原始彩图没有截掉盒口四边。下图为400–800mm相机端HeightExtract过滤开启时的深度结果，大片盒沿缺测，算法错选了更深的内区。此时输出的448.225mm是失败候选深度，不是有效外框位置。

结论是**完整位于RGB视野内，但近端被设置的深度窗口裁掉**。400mm是本次用户要求和采集过滤阈值，不是证明过的相机硬件测距极限。不能再将本例仅归为反光或“160算法天然无法定位”，也不能通过长期改成350mm宣称满足400–800mm要求。

350mm对照仍采用已有外框算法，存在既有160外框与真实工装配合中心的偏差风险；这里只用其确认外框成像恢复，未把该位姿作为运动目标。真实端子、接地目标、绝对精度及工装配合仍须单独核验。

## 对腰姿求解的影响与现场状态

旧候选腰姿`[-30,20,10,-80]°`的完整非接触模型结果保留，但当前实测工位已与设计不同，不能直接当现场成功结论。固定世界相机时，单独改变腰姿不能消除160近于400mm的成像问题；后续需在同一底座和三型约束下处理相机至目标距离，再联合验证实际工位的共用腰姿和路径。

最后已恢复160检测页WorkingMode=4、400–800mm采集，原活动标定保持。132与160采集时腰部模型角约[-27.874,23.290,18.760,-5.704]°，与早先标定参考J4约-13.735°不同；在线132结果使用实际腰姿重投影且状态监控有效。没有下发任何上电、腰部或机械臂运动命令。
