## 公共类别校准接口

新增共享 `calibration.py`：可按**预测排名第一的检测候选类别**设置置信度和第一/第二候选分差门槛。输入为公开候选类别 [N,8]，不读取真实角色、目标类别、任务阶段或未来动作。没有类别配置时保持原全局校准逻辑；请求类别配置却缺少公开类别时明确报错，不能静默忽略。空目标不会因类别门槛变成非空框。

批量确认、逐帧runtime、跨搜索选择和包导出统一使用同一校准函数。推理包保留 `class_thresholds`/`class_margins`及其必要源码，仍标为研究候选。没有增加策略 token，也没有增加选择器的观测维度。

41 项相关测试通过，5 条既有依赖弃用警告。旧全局配置回归：910 帧/34episode，流式与批量接受槽差 0，概率最大差 1.79e-7。类别配置同样 0 槽差，且重复 step 幂等；选择器 CPU 中位约1.206ms、P95约1.447ms，不含前端或动作策略。复制推理包至隔离目录、python -I仅导入包内API重放910帧，类别配置概率/选框与原工程均为0差。

## 完整开发搜索结果：暂不进入第七组

固定第六组融合模型，只比较拒选规则。第一轮预测bowl门槛 [0,.25,.4,.5,.6,.7,.8]、其他类别门槛 [.4,.5,.6,.7,.8]，每个门槛对比较全局margin [0,.1,.2]。共35个门槛对+2个完整固定配置控制=37记录、107校准点。第二轮对相同35个门槛对另比较bowl专用margin [0,.1,.2]及其他类别margin [0,.1,.2]，37记录、317校准点，0次新拟合。

每个校准点仍要求相对原始指针及原冻结模型的combined24、old8、new16 V4门槛全部通过；未知帧、逐角色分母和切换定义不改。参数、完整阈值点、失败和成功均保留。两轮合计74条配置记录（424个含固定控制的校准点），累计已完成比较1289条；记录包括重复对照和参数，不是算法数。

两轮各6条记录合格（包含冻结融合控制及其等效配置）。最好的开发预测相同：只多对一个持碗框，取碗错类与即时切换未改善，另外接受两个错误，精度略降、类别抖动略增。第一轮胜出bowl门槛0、其他.6、全局margin.2；第二轮为bowl门槛0、其他.6、bowl margin.2、其他margin0；bowl阈值0/.25/.4/.5在这些开发点上的最优结果相同。

降低bowl门槛至.5、margin0可将开发正确数提高到1136，但新16条dev的类别抖动高于原冻结模型，门槛拒绝该点。不能只看总体正确数，也不能为修复第六组0.552这一帧而采用它。最优合格规则仍要求bowl margin.2，并不能据此声称修复该拒选原因。

因此这两轮没有证明新的取碗/切换收益，不将这个1帧持碗开发增益送入第七组确认，不替换已有模型。第七组继续保持未标注、未提取候选、未评分。第六组保留为已查看诊断/回归，无新确认结果。
