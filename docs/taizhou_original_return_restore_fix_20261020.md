## 返回行为

正常流程原本就应在检测对位暂停后，通过“撤离并返回初始位”从next_segment继续原完整路线，不需要重新搜索收臂通路。此次故障发生在软件更新重启后：完整路线归档还在，但内存中的到位进度丢失，独立复位入口无法关联原返回段，继而错误地进入普通收臂搜索。

修复后：

- 完整路线确认检测暂停段执行完成后，原子保存HMI计划身份、摘要、完成进度及input/plan/receipt归档摘要。

- 视觉、标定、工位、工具或静止部件变化仍拒绝复用。控制器运动学模型变化时，只提取原关节路径，以当前模型重新检查全部返回关节线；旧碰撞回执不能直接授权执行。
- 在下发新的路线运动前撤销旧返回记录，避免已经开始返回后又从检测终点重新执行。
- 页面在新脚本加载后明确区分“复核原完整路线的撤离返回段”；JS/MJS等网页代码统一使用no-cache，减少版本更新后旧脚本缓存干扰。
