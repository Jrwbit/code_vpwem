## 结论

补标改善了抽屉召回，但未解决抽屉把手可靠性。YOLO640 仍可作为速度基准，不能作为六类均达到 95% 的正式感知输入。Mask R-CNN 在洗碗机把手上更合适：合并测试集 Precision 96.97%、Recall 82.05%；抽屉把手仍只有 70.83% / 45.54%。不替换现用检测器，不重启旧 A1 预处理。原先因感知质量暂停的状态保持。

主视觉混淆已修正：对象缓存中的红碗框不再重画策略主 RGB；离线直接保留原 BoxedNoHistoryDataset 输出，在线独立调用旧 PrecisionSequenceDetector / OnlineBoxedRGB。基线本来存在“离线红碗 GDINO 缓存、在线 combined_blend”这一差异，本次保留且显式记录，不把它描述成原来离在线完全一致。

针对 table_setup_from_dresser_expert、unload_dishwasher_to_dresser_suboptimal，固定 seed=20261101，按 episode 身份和均匀时刻选帧，不根据测试误差挑帧。既有 6 个训练 episode 加密到 32 个时刻；增加 4 个训练 episode，各 32 帧；另增 2 个 valid-source episode，各 16 帧，只作确认测试。

新增 340 帧全部通过 RGB 对齐检查，共 1,699 实例（训练 308 帧、确认测试 32 帧）。合并首轮后为 555 帧、2,813 实例：训练 398 帧 / 1,975 实例，dev 62 帧 / 357 实例，test 95 帧 / 481 实例。原测试 63 帧 / 305 实例保持，新增确认测试 32 帧 / 176 实例另报。

沿用已修正的 CAD 可见像素标注、每个抽屉一个连续把手、xyxy 右下边界排他定义。逐帧概览和抽屉/把手类别图已由助手复核；所有像素数、mask 紧框和原 RGB SHA256 检查通过，各 split 无相同 episode、无完全相同 RGB。仍属于仿真辅助参考，不是独立人工逐像素 GT。极小可见部件保留，不能因难检测就删除测试目标。

## 训练与评估规则

YOLOv8n 在 640 输入上从同一 COCO 预训练权重重新训练 100 epoch，seed100、batch16、FP32，其他超参与首轮一致，用时 263.46 秒。Mask R-CNN 同样从原 COCO 权重重新训练 25 epoch、batch4，用时 317.06 秒。两者在卡4并行，保持原有其他任务运行。新增样本导致每 epoch 更新次数增加，因此这不是等优化步数的数据量因果消融。

模型权重分别按各自原有 dev 指标选择；六类阈值只在原 62 帧 dev 上选择，固定后评价测试。95% dev precision 选择仍只要求至少 5 个预测，这是探索阶段的工作点，不能证明总体 precision 的置信下界达到 95%。所有模型统一类别、RGB 输入、逐类 NMS=0.5、class0 红色支持过滤、IoU>=0.5 一对一匹配。补标前权重也在同一 95 帧测试上重评。

下面是完整检测输出的指标（最多100框），不是实际 memory 8 槽截断后的指标。P=Precision，R=Recall，单位 %。

## 关键类别（合并95帧）

| 方法 | 抽屉 P / R | 抽屉把手 P / R | 洗碗机把手 P / R |
|---|---|---|---|
| YOLO640 补标前 | 95.35 / 50.00 | 86.96 / 17.86 | 100.00 / 51.28 |
| YOLO640 补标后 | 96.40 / 65.24 | 54.29 / 16.96 | 100.00 / 12.82 |
| Mask 补标前 | 96.25 / 46.95 | 55.74 / 30.36 | 84.85 / 71.79 |
| Mask 补标后 | 90.52 / 64.02 | 70.83 / 45.54 | 96.97 / 82.05 |

补标后 YOLO 抽屉为 107TP / 4FP / 57FN，抽屉把手为 19TP / 16FP / 93FN。其 dev 把手阈值 0.70 在 dev 上仅 8TP、0FP、72FN，在新 episode 上泛化不足。洗碗机把手阈值升至 0.95 后，合并测试仅 5TP、0FP、34FN；100% precision 伴随 12.82% recall，不能当作可靠识别。

补标后 Mask 洗碗机把手为 32TP / 1FP / 7FN，抽屉把手为 51TP / 21FP / 61FN。即使总体召回提高，抽屉与抽屉把手 precision 仍没达到目标。下一轮首先应增加独立 dev episode 的部件覆盖，并检查小部件像素尺度/标签边界，而不是继续用很少 dev TP 调高阈值。

本轮时延包含同卡任务竞争，未据此重新排序检测速度；仍保留原空闲卡测量作为历史数据，不宣称新的时延优于原值。

## 容量诊断与共享约束

新增 340 帧中 58 帧可见相关对象超过 8 个，最多13个。按 class-balanced confidence 规则在 dev 阈值过滤后模拟截断：

| 方法 | 不截断 TP / FP | 8槽 TP / FP | 16槽 TP / FP |
|---|---|---|---|
| YOLO640 补标前 | 272 / 10 | 270 / 9 | 272 / 10 |
| YOLO640 补标后 | 289 / 25 | 289 / 25 | 289 / 25 |
| Mask 补标前 | 288 / 50 | 288 / 42 | 288 / 50 |
| Mask 补标后 | 339 / 42 | 335 / 30 | 339 / 42 |

本轮 YOLO 补标后主要瓶颈不是8槽截断，8槽和16槽均289TP/25FP；Mask 补标后8槽丢掉4个TP，同时过滤12个FP。容量不能用测试 precision 提升来选择。当前历史配置仍为8槽，没有暗改或复用不兼容缓存；正式协议若升16槽，A1/A2/A3必须同时切换，并明确与8槽的差异。

三组继续共用检测权重/版本、dev阈值、类别顺序、ROI与归一化、实例关联与排序、visible/seen/box有效性、物理观测更新时刻、容量/淘汰、训练配方及初始化。仅 mode 和输出目录可以不同。新增 YOLO 接入应另建缓存；当前默认的历史 GDINO 对象分支仍是暂停的旧原型，不能把它冒充为新 YOLO 输入。

新增独立主视觉协议 independent_main_visual_v2：记录旧画框 detector 元数据，固定 combined_blend bundle SHA256=af62860467a1c95d2e60a9df5d89ee1b9001116cb45c1aa7a285c1810f6f7c07；替换 bundle 会报错。旧对象协议不能直接通过新版评估。原工作基线 tag momart-boxed-working-20261030 保持。
