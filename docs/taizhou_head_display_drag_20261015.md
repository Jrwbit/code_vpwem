## 结果

- 手眼页面新增头部复位预览、确认和停止。头部两轴回控制器 0°，每轴误差 ≤1°，保持启动时实际腰部位置；1% 速度，最大变化 30°，原生运动最多 30 秒。SDK 只读确认头部为本体外部轴 axis1/axis2、映射为 1/2；配置中的软限位单位为度，转换为弧度后用于前后端校验。原始目标、启动姿态、身份、限位、30 秒预览令牌、启动代次、确认、心跳和退出保护均生效。头部继承腰部启用范围，仅开放回零，不开放任意头部目标。
- 腰部保存姿态复位的到位容差、头部参考漂移容差统一为包含边界的 1°；模型与真机匹配容差原本就是 1°。控制器软限位和目标保留的 2° 余量未改变。
- 当前本体 SDK 已恢复非零反馈。撤回上一轮对两套渲染模型固定减 90° 的处理：渲染直接使用后端 URDF 模型角，数值和滑条使用控制器角，腰部第二轴模型角仍为控制器角加 90°。单次全零反馈及用户当时看到的零度不能证明运动学零位已经改变。
- SDK `getRobotCfg_DHparam(True)` 显示两臂名义段长 332/278 mm，原资产为 314/260 mm；URDF 末端固定段 92 mm 改为 SDK 名义 90 mm。服务器只为浏览器生成修正后的 URDF，不覆盖原资产和后端标定计算。原网格仍为旧资产，外观及整机安装关系不能据此视为已验收。
- 使用同一 arm_tcp 固定端点对比 SDK flange，当前样本位置差异从左臂约 33.77 mm／右臂约 23.99 mm 降为约 1.35 mm／0.095 mm；旋转差异约 0.262°／0.133°。这些是单姿态名义模型核对结果，不是现场定位精度验收。调查中最初约 8–11 cm 的对比将 link7 原点当成法兰，混入了端点差异，已纠正，不能作为正确端点误差使用。离线测试另在两个不同姿态、两臂验证了修正几何与 SDK 名义八行 DH 链一致。
- 现场多次拖动中止日志明确为 `new controller error during button drag`，对应 41464：关节太靠近限位，控制器拒绝开始拖动。当前左臂 J7 约 90.04°，上限 90°。新增上电前的 2° 限位余量检查，返回具体关节、角度、限位和余量，拒绝启动写入任务；现场应使用示教器低速向内调整后重新预检。2° 是程序检查余量，不能保证厂家一定放行；没有自动退限位、自动重试上电或忽略厂家报警。原生错误现保留控制器编号和完整报警文本。
