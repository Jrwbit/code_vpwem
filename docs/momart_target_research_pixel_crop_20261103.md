# 主视角像素裁剪增强，2026-11-03

前一轮76条边缘权重对照未证明核心错误或最小目标改善，本轮转为重新生成一致的像素、候选和几何，不把旧特征配上缩小的框冒充图像增强。

## 导出前协议

仅使用既定108条训练轨迹的5794个已知目标查询。开发、test、回归、已查看确认9及封存确认10均不生成训练增强。每个查询从120×90主视角选择96×72视窗，缩放回120×90；当前t与过去t−8使用同一裁剪，深度与实例掩码同步最近邻变换，RGB双线性变换。选择参数可以用训练目标掩码制造保留2/4/8px的部分目标，但该特权只用于离线增强选择与匹配标签，不进感知器或模型特征。不可行时固定seed随机裁剪，不删除原训练帧。

冻结Mask R-CNN在裁剪后RGB重新检测；冻结主RGB编码器重新计算ROI/全局特征。裁剪后掩码重新确定可见实例框，IoU≥.5匹配目标提案；裁出画面或无匹配提案按既有无目标框slot8规则处理，不能继续用原始可见框监督。它表达框不可用，不代表没有操作意图。原始5794条训练仍完整保留，只增加一个裁剪版本。

机器人自身3D相对位置与proprio不变；主相机投影UV及其过去差分按图像仿射映射，深度点反投影先逆裁剪映射回原传感器标定坐标，再用原FOV计算3D位置。原14维上下文里的FOV仍是源相机标定；这不是模拟物理相机移动。默认未裁剪box_geometry路径不变，恒等仿射与旧输出逐元素一致。

## 64帧实际管线检查

物理GPU1导出64个训练查询并退出0：16帧由原来非细条目标变为≤8px部分目标，全部64目标仍可见，重新检测后52帧有匹配目标；16个定向细条中仅7个有匹配提案。说明检测可用性可能成为瓶颈，不能把裁剪框的存在当作感知成功，也不能把新增slot8监督称为目标识别改善。

输出候选[64,8,155]、上下文[64,449]，均float32且有限；valid/positive为bool，label与base_index为int64。计划保存源RGB/掩码/原manifest/标注/实现SHA、逐查询crop与严格训练隔离。没有读取腕部/侧面、未来帧/命令或GT对象3D状态。

65项相关测试通过：图像/掩码坐标、裁后可见框与被裁出目标、同一仿射处理两时刻、UV及射线反投影一致、恒等几何精确复现；5条既有依赖弃用警告。64帧只是导出管线验证，不是训练收益或独立确认。

复现：`export_crop_training.py --root OUTPUT_ROOT --config GPU_CONFIG --output NEW.npz --device cuda:0 --batch-size 16`。`--max-rows 64`为明确的smoke子集，不能作为全训练归档；`--plan-only`只生成计划。输出拒绝覆盖既有结果。完整新训练比较须等全量归档验证后执行，确认10仍raw封存，目标active。
