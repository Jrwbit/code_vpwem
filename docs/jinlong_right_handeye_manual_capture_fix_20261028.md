# 右臂手眼标定解算失败：采样选臂修复（2026-10-28）

## 结论

用户使用原厂示教器移动右臂、标定板也随右臂移动，但原手眼网页在新组手动采样时默认读取左臂。当前22张照片被错误地配对到几乎不动的左臂位姿，因此无法解算。曝光调整后角点识别正常，故本次失败不能归因于过曝或照片数量不足。

已修复并部署：新组必须明确选择采样机械臂，样本列表与采集回执显示机械臂；已有样本锁定本组的机械臂，禁止混臂。旧网页不提交机械臂时拒绝采集并提示刷新。原22组保留为诊断证据，新右臂组已实采并核验首份样本；完整标定仍需用户继续改变右臂姿态采集。

## 实现与验证

控制源码提交：`464465ad642dfb0373bd447f7c648f27a1ae0608`；工控机提交：`b5eb49f1ae73156a60d559b8a7d7ab7428d52d68`。

- 手眼页增加独立的“采样机械臂”选择，与拖动控制选择分开；首样本后锁定该组机械臂，每行显示左/右臂。
- HTTP手动采样必须提交明确的 `arm_role`；服务端检查其与活动拖动/自动标定会话、已有样本一致。示教器静止采样可以直接读取右臂，保持原停稳、新鲜反馈、腰姿和曝光期间姿态检查。

- 单方法的非有限解或SVD失败记入该方法错误，继续核对其余方法；没有有效解仍报失败，不伪造矩阵或跳过质量门限。
