# VPWEM / PER 全量实验逐点对照

更新时间：2026-08-13（Asia/Shanghai）

本文按“论文数字—本机复现—服务器复现—PER 对照”逐点展开。所有成功率均为百分比；`pp` 表示百分点。`约`表示从论文柱状图读取的近似值，不能替代作者原始数表；没有实际运行的格子写作“—”，不把同步文件或不同配置结果冒充独立复现。

## 一、论文主图：VPWEM 的训练与推理结构

![论文 Figure 2：VPWEM 主方法、训练和推理流程](assets/vpwem_detailed_audit/fig2_main.png)

论文主线是：保留近期观测作为 working memory，把更早的单回合历史用 Q-Former 递归压缩成固定数量 episodic tokens，再与当前观测一起条件化 diffusion policy。训练时联合优化 memory compressor 与动作策略；推理时在线更新固定容量记忆。

## 二、对比口径与配置漂移

| 项目 | 论文主配置 | 当前复现/实验 | 可比性影响 |
| --- | --- | --- | --- |
| Diffusion 层数 | 8 | Robomimic 标准四任务多为 4；MIKASA/MoMaRT 为 8 | Robomimic 只能称本机变体 |
| Compressor 层数 | 2 | 主结果尽量选 Q-Former 2 层；旧运行曾混入 1 层 | 已从汇总中排除已知混入项 |
| Memory token | L=2，S=2 | 主复现基本一致 | 可比 |
| Memory bank | FIFO，容量 8 | VPWEM 主结果 FIFO；PER 改为事件选择容量 8 | PER 是方法变量 |
| 历史 subsample | MIKASA 5，其余 20 | 主复现依任务设置；旧配置存在漂移 | 需随 checkpoint manifest 再核验 |
| Batch size | 64 | 不同运行存在差异 | 影响严格复现结论 |
| 训练步数 | MIKASA 600k；其余 1M | 主结果按 600k/1M；PER 额外等预算适配 10k | PER 只与其等预算 FIFO 对照 |
| 评测样本 | 论文图未给逐点 episode 文件 | 主复现多为每 seed 30；PER 正式为每模型 300；跨基准为 100 | 不同表的方差不可直接横比 |

机器来源说明：Robomimic 主结果在本机；MIKASA/MoMaRT 主训练评测在服务器 `10.1.77.25`。服务器结果清单被同步到本机用于审计，但不算“本机独立复现”。

## 十五、最终判断与下一步

1. VPWEM 可以继续作为论文主体，但表述应收窄为“固定容量的单回合观测历史压缩”，并清楚区分严格复现与 4-layer 本机变体。
2. PER-delta 暂时降级为探索性消融或负结果分析，不能写成“稳定涨点”的核心创新。
3. 第一优先级是修复 RememberColor3 与 LongSquare：核对数据版本、episode 边界、历史采样、8-layer 配置、eval wrapper，并保存完整 manifest 与逐 episode 结果。
4. 若继续验证 PER，只在一个已达到论文 FIFO parity 的 memory-intensive 任务上冻结唯一候选，使用至少 5 个训练 seed、每 seed 至少 300 个未见公共 episode。
5. 下一代 retention 更适合改为 query/task-conditioned：用 policy query、动作不确定性或未来 action/value 预测误差评价槽位，而不是仅用相邻视觉 embedding delta。

## 十七、论文—FIFO 复现—PER 三方对齐诊断

这一节专门回答“点数低是基线没有复现，还是 PER 本身不好用”。必须拆开两个差：

1. **复现差距** = 同轮配对 FIFO − 论文 DP-VPWEM。它衡量进入 PER 对照前，基线是否已经达到论文水平。
2. **PER 净效应** = PER − 同 checkpoint、同训练预算、同评测初始状态的 FIFO。只有这个差能相对干净地归因于 PER。
3. **PER 对论文差距** = PER − 论文 DP-VPWEM。它方便看最终绝对水平，但不能单独用于因果归因，因为论文与复现的配置和评测协议不完全相同。

### FIFO 与 PER 到底改了什么

| 维度 | FIFO VPWEM | PER-delta VPWEM |
| --- | --- | --- |
| 写入原则 | 采样到历史帧后按时间顺序写入 | 计算相邻 embedding 的 `1-cosine` 变化，超过阈值或达到最大等待间隔才写入 |
| 满容量淘汰 | 删除最老槽位 | 按事件效用/衰减分数替换低价值槽位 |
| 容量 | 8 | 8 |
| 输出给策略 | Q-Former 压缩为 2 个 memory tokens | 同一个 Q-Former，仍压缩为 2 个 tokens |
| 试图保留的信息 | 最近发生的历史 | 表征变化较大的“事件” |
| 主要风险 | 关键但较早的信息会因时间被挤出 | 视觉变化大不等于决策重要；可能保留干扰事件 |

因此 PER 对照不是“多给了 memory token”，而是只改变固定容量 bank 的写入和淘汰规则。正式 Transport 对照还给 FIFO 和 PER 相同的 10k 适配预算。

### 三方对齐后的结论

1. **不能把 PER 总体无增益全部解释为复现太低。** ShellGameTouch、cleanup→sink/expert、setup←dresser/expert 的配对 FIFO 已接近论文，但 PER 分别下降 12、4、6 pp。
2. **也不能把所有低点都怪给 PER。** RememberColor3 在使用 PER 之前，FIFO 就比论文低 76 pp；这里首先是复现失败，PER 的 +6 pp 不能弥补根因。
3. **PER 不是完全无效，而是高度任务相关。** cleanup→sink/suboptimal、setup←dishwasher/suboptimal、unload/suboptimal 分别为 +9、+4、+12 pp；但另一些已复现任务显著或明显下降。
4. **当前最合理判断是 delta 事件规则不稳定。** 它在部分任务保留了有用事件，在 ShellGameTouch 等任务可能把“视觉变化大但决策无关/有害”的历史保留下来。
5. **论文创新决策仍不变。** Transport 正式测试只有非显著正向趋势，跨基准总计为 -0.25 pp，因此不能写“PER 普遍优于 FIFO”；可以写任务异质性、机制干预和失败分析。
