## 5. 每组实验能获得什么信息

| 实验组 | 主要回答的问题 | 不能单独回答的问题 |
| --- | --- | --- |
| No-History strict | 当前两帧观测本身能达到多少成功率；历史是否必要 | Q-Former是否优于其他历史编码器 |
| Direct-History strict | 不做学习式memory压缩，直接提供空间历史是否足够 | 若token预算不同，无法判断收益来自结构还是更多token |
| VPWEM strict | Q-Former固定容量压缩的正式性能 | 缺少前两组同协议时，无法做严格归因 |
| ShellGameTouch Direct-History | 早期cue能否通过anchor空间token影响后续决策 | 不做wrong/zero anchor干预时，无法证明模型真的读取了history |
| RememberColor5 Direct-History | 五分类长记忆上的低成本可行性 | 基线接近机会水平时，无法判断方法上限 |
| MoMaRT Direct-History | 方法能否泛化到长时程、多阶段操作 | 没有No-History和同协议VPWEM时，不能归因于memory结构 |
| 400k Robomimic初筛 | 快速排除明显不工作的方案 | 不能代替1M严格对照或多seed统计 |
| checkpoint曲线 | 收敛速度、checkpoint选择敏感度 | 不能证明新方法提升 |

## 7. 尚未运行但重要的实验

按优先级排序：

1. **同协议三方对照**：No-History、Direct-History、VPWEM-QFormer使用相同数据、训练seed、optimizer steps、effective batch、8-layer decoder和评测episode。
2. **Token-matched Direct-History**：把历史最终压到与VPWEM相同的2个tokens；否则4×4空间历史拥有远高于VPWEM的token预算。
3. **历史组成消融**：无历史、仅anchor、仅recent-3、anchor+recent-3、VPWEM。
4. **因果history干预**：ShellGameTouch上评测correct anchor、wrong/shuffled anchor、zero history、random history。
5. **strict早期门控**：20k/50k/100k checkpoint，各用固定少量rollout决定是否续训。
6. **效率对照**：同步报告参数量、history token数、峰值显存、训练吞吐和推理延迟。
7. **统计复验**：只有seed100出现明确正点后，再扩3个训练seed和至少100个配对episodes。
8. **MoMaRT正式评测入口**：先为现有200k/400k checkpoint补统一评测脚本和固定episode列表。
