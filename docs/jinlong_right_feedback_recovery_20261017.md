# 珞石控制窗右臂反馈与恢复按钮（2026-10-17）

## 当前结论

现场反馈右臂弯曲，但控制窗显示七轴全零/伸直。检查后不能将其认定为前端正负号错误：`.160` 控制器型号为 `AR5-5_0.8R-W4C5C11`，设备身份与既有右臂记录一致。上一批右臂手眼标定的 7 组非零关节角，通过名义显示模型与保存的 SDK 法兰位姿复查，最大位置差 0.819 mm、角度差 0.1592°，没有证据支持随意翻转七轴方向或设置新零偏。

只读诊断得到：

- 普通 `Robot_T::jointPos`、`BaseRobot::jointPos`、`getStateList().joint_pos` 都是零。
- 实时测量字段 `q_m`、`dq_m` 和电机位置 `theta_m` 连续三帧均为零，接口返回成功。
- 单独重连右臂只读 SDK 进程，读数仍未恢复。
- 已直接打开工控机原厂 RobotAssist，连接 `.160`。原厂提示客户端当前为 L 机型，与连接的 R 机型不符。备份客户端配置后，按提示适配 R 机型并重启、重新连接；界面确认 `.160:5050` 与 `.160:4567` 均连接，选中 R 机型。其“状态监控 / 位姿 / 关节(°)”同样显示七个零。

因此当前只能确认**控制器侧给出的轴位置与用户描述的实物姿态不一致，真实关节反馈尚未恢复**。没有凭这些零值推算实际姿态、修改关节零位或宣称标定恢复。也没有据此断言编码器损坏；底层轴反馈、控制器状态与零位仍需要原厂侧进一步诊断。

## 已部署的软件处理

控制窗“仿真”页右臂区域新增“重新读取并修复右臂显示”：

1. 仅停止并重建右臂的已有只读 SDK 子进程；左臂、腰部和相机进程不重连。
2. 用读取代次隔离旧缓存帧，等待重连后的新反馈。
3. 校验机型、控制器地址/ID、七轴原始值与模型映射、名义 FK 与 SDK 法兰位姿。FK 的 5 mm / 1° 门限仅检查严重映射错误，不是定位验收标准。
4. 只有获得可信反馈，才同步右臂七轴目标并重新加载页面/模型。
5. 硬件反馈七轴精确全零时显示 `right_zero_feedback`（即使力矩已经有变化，也不能靠力矩确认这些零角是真实零位），不给出“修复成功”；真机角度显示为空，暂时隐藏右臂模型，避免把默认伸直姿态标为真实姿态。真实零位仍需独立确认，不能通过猜测消除此状态。

本次实机读链路检查中，按钮返回 HTTP 409 / `right_zero_feedback` / `reader_reconnected=true` / `controller_writes=false`，符合当前未恢复的事实。它不是一键修改控制柜零点的按钮。

采样、回放、计划或运动期间拒绝恢复操作。原有 `latched=true` 控制锁定在服务重启后保留；没有执行运动、上电、清报警、修改零位，也没有改变活动手眼标定的 SHA256。相机常驻进程仍为 PID 515538，模式就绪。

初始缺少右臂可信反馈时，其余正常部件仍可显示，完整仿真就绪与运动条件不会通过部分反馈被放宽。
