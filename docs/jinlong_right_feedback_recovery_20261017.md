## 已部署的软件处理

控制窗“仿真”页右臂区域新增“重新读取并修复右臂显示”：

1. 仅停止并重建右臂的已有只读 SDK 子进程；左臂、腰部和相机进程不重连。
2. 用读取代次隔离旧缓存帧，等待重连后的新反馈。
3. 校验机型、控制器地址/ID、七轴原始值与模型映射、名义 FK 与 SDK 法兰位姿。FK 的 5 mm / 1° 门限仅检查严重映射错误，不是定位验收标准。
4. 只有获得可信反馈，才同步右臂七轴目标并重新加载页面/模型。
5. 硬件反馈七轴精确全零时显示 `right_zero_feedback`（即使力矩已经有变化，也不能靠力矩确认这些零角是真实零位），不给出“修复成功”；真机角度显示为空，暂时隐藏右臂模型，避免把默认伸直姿态标为真实姿态。真实零位仍需独立确认，不能通过猜测消除此状态。

本次实机读链路检查中，按钮返回 HTTP 409 / `right_zero_feedback` / `reader_reconnected=true` / `controller_writes=false`，符合当前未恢复的事实。它不是一键修改控制柜零点的按钮。

采样、回放、计划或运动期间拒绝恢复操作。原有 `latched=true` 控制锁定在服务重启后保留；没有执行运动、上电、清报警、修改零位，也没有改变活动手眼标定的 SHA256。相机常驻进程仍为 PID 515538，模式就绪。

初始缺少右臂可信反馈时，其余正常部件仍可显示，完整仿真就绪与运动条件不会通过部分反馈被放宽。
