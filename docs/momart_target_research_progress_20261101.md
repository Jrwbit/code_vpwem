# 单目标选择持续研究：首轮独立确认未达标

目标保持 active。用户要求继续实测可行方案，研究不在一次失败后终止。目标为提高抓碗、操作碗架/把手、持碗阶段的目标框可靠性，并维持正确框召回和阶段覆盖。当前仍未替换正式模型、未接入扩散策略，以下是离线框选择代理评分，不是机器人任务成功率。

## 实测结果与方案取舍

累计完成215个配置：44个基础/腕部/深度/软角色/GRU/树/记忆配置，25个机器人与深度几何配置，50个跨模型融合与独立框质量配置，96个角色分类及因果状态滤波配置。配置数包含参数组合，不能写成215种独立算法，更不代表穷尽所有方法。

原开发集仅45个有标签帧，源自4条轨迹。仅按总体精度选择曾会拒绝所有碗架操作帧，因此验收修订2要求：每个至少3个可见开发样本的角色保留至少1个正确框，且报告逐角色召回。阈值、模型、混合系数和检查点均只用原train/dev选择。首次确认集8条轨迹在搜索前冻结；606候选帧经原有图像对齐检查保留575帧，其中415帧具有明确代理标签，412帧目标可见。其余160帧不是“无目标”负例。

最终按开发集选中的空间查询模型，加0.1的前两候选概率差拒选，开发集精度35/38=92.11%，正确框召回35/45=77.78%。新8条轨迹的冻结验证如下：

目标未达成：87.56%低于90%。逐轨迹平均召回旧模型85.35%、新模型84.49%，因此不能只凭合并帧指标宣布整体提升。抓碗和持碗错类下降，但碗架角色仍仅20/46=43.48%正确框召回，门把手召回31/43下降到30/43，抽屉把手52/57下降到51/57。成功处和退步处都保留。以轨迹为单位做10000次配对bootstrap：选框精度差为+2.37个百分点，95%百分位区间[-2.15,+6.71]；合并帧召回差+0.24个百分点，区间[-5.32,+5.41]。两个区间都跨0，8条轨迹尚不足以证明稳定改进。

后续96个软角色/时序组合只用原开发集选取。该轮最佳是当前帧的弱角色先验，开发32/33精度96.97%、32/45召回71.11%，低于上一轮的开发召回；因果时序版本未超过前一方案。不能把更高精度、较低覆盖当作新赢家。首次确认集现已查看，后续只能作为已检查回归数据；不会继续调它再称“独立验证”。

## 方法与输入审计

修正持碗阶段的标签：缺少放置接收区域标签，不代表当前操作主体消失。当前持碗主体仍为碗；释放/边界证据不足的帧设为未知，而不是空目标。所有新对照统一重训、重评，旧标签协议百分数不混比。运动、未来接触近似和仿真可见网格只用于弱标签/评分，不能称独立人工意图真值。

机器人几何只用自身头部关节、躯干升降关节、夹爪位置与当前观测深度。CPU PyBullet只加载机器人URDF，不加载场景对象。离线从存档提取机器人关节块时校验头部角度及末端FK，唯一匹配偏移440，各源末端误差中位数小于1毫米、P95最高约3.3毫米。在线接口额外需要暴露现有机器人trunk_joint_pos；它不在原10维proprio里，不能声称完全无需增加观测。推理不读取场景物体位置、动作或未来帧。

几何候选特征包含框内观测深度到夹爪的距离与相对方向，以及夹爪投影和候选框关系。融合尝试线性平均不同模型；独立框质量模型用train中同类IoU>=0.5的可见网格参考监督，预测框是否可靠，不使用目标意图。低质量移除的概率转入空槽，不强制换成另一个物体。因果滤波只读取当前和过去观测，分轨迹重置状态，角色转换统计只来自train，未标注区间不强行连成转换标签。

首轮确认的Mask推理最初发生GPU显存不足：空闲GPU被原有基线进程重新使用。未停止其他任务，改用CPU batch4完成575帧。所有比较共享同一组确认候选框；CPU/GPU浮点和NMS可能略有差别，未宣称与训练GPU batch64逐位一致，也未将CPU离线速度当作部署速度。旧预测保存及新推理加载路径在910帧回归输入上验证完全一致（最大概率误差0）。
