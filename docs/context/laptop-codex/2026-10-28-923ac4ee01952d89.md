第一次画图，用这段：

```text
请基于当前项目，制作一张适合顶级学术会议论文的主图（方法/系统总览图）。

【项目理解】
先阅读 README、核心代码和相关文档，梳理：
- 项目解决的问题、输入和输出；
- 核心流程和模块关系；
- 最值得突出的方法贡献。
根据实际实现绘图，不编造模块、实验数据或性能提升。
无法确定的内容明确标注“待确认”。

【内容组织】
让读者在 10 秒内看懂：输入是什么、方法如何工作、核心贡献在哪里。
主流程优先从左到右，必要时分成 Overview 和核心模块放大图。
用视觉重点突出核心贡献，辅助模块保持简洁。
箭头必须表达明确的数据流、控制流或交互关系。

【视觉要求】
白色背景、克制配色、清晰的信息层级、统一字体和线宽。
模块对齐，间距均匀，避免交叉箭头和长段文字。
使用简洁的矢量图形说明机制，避免整张图只有文字方框。
缩小到论文排版尺寸后，文字和关键细节仍应清晰。

【交付】
1. 可编辑源文件 figure_v1.svg。
2. 高清预览 figure_v1.png。
3. 本地预览页 preview.html，支持放大查看。
4. 简短说明各模块对应的代码或文档依据。

为 SVG 中的主要模块设置稳定的 id，方便后续局部修改。
直接完成初稿并检查文字溢出、元素重叠和箭头连接。
```

在这个基础上修改，用第二段。**关键是指定修改范围，并锁定其他布局：**

```text
请基于 figure_v1.svg 进行局部修改，生成 figure_v2.svg。

本次修改：
1. [例如：把核心模块展开为三个子步骤]
2. [例如：增加从检测结果到控制模块的反馈箭头]
3. [例如：把输出区域改成三个并列结果]

除上述修改及其必要的连接调整外，保持其他模块的位置、
尺寸、字体、颜色、画布和文本不变。
如果局部空间不足，采用最小范围的布局调整，并说明调整了哪里。

保留 v1，输出：
- v2 可编辑 SVG 和高清 PNG；
- 改动标注图：用橙色框标出变化区域，旁注说明删除项；
- 更新 preview.html，展示“修改前｜修改后｜改动标注”；
- 三张图使用相同画布、缩放和对齐基准；
- 提供 v1/v2 原位切换，便于观察元素移动；
- 附上简短修改清单。

正式版图片不带改动标记。
```

直观看改动时，最有用的是这三种视图：

| 视图 | 适合检查 |
|---|---|
| 修改前后并排 | 整体布局、信息是否更清楚 |
| 同一位置切换 v1/v2 | 哪个模块移动了、尺寸变了多少 |
| 橙色标注变化区域 | 有没有遗漏要求、误改其他部分 |

**方法框架图优先保留 SVG 源文件。** PNG 适合展示；SVG 能精确修改文字、箭头和模块，也更容易保持多轮修改后的布局一致。
