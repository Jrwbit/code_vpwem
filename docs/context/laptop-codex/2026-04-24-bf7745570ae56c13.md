## assistant — 2026-04-24T08:33:53.578Z

不一定“必须用 dataset”。当前代码里 `--dataset-path` 的真实作用主要是：给 policy 补上训练时的数据归一化参数 `normalizer`。

在 [run_rm75_dp_dryrun.py](/[REDACTED long identifier].py:237) 的 `load_policy()` 里：

- 先加载 checkpoint
- 如果传了 `--dataset-path`，就实例化训练 dataset
- 调 `dataset.get_normalizer()`
- 把 normalizer 塞回 `workspace.model` / `ema_model`
- 然后在线推理时用这个 normalizer 归一化 `joint_state`、反归一化 `action`

所以 dataset 不是为了在线推理时拿样本，也不是为了真机动作本身。它是为了恢复训练时的数值尺度。

为什么这个重要：

- 模型训练时看到的关节和动作不是原始度数，而是 normalized 之后的值
- 推理输出的 action 也需要按同一套统计量 unnormalize 回真实关节目标
- 如果 normalizer 不一致，模型输出的动作尺度会错，真机上可能表现成不动、乱动、幅度异常

但从代码看，`--dataset-path` 是可选的：

```python
parser.add_argument("--dataset-path", default=None)
```

如果 checkpoint 本身已经带了可用的 `normalizer`，就可以不传 dataset。否则会报：

```text
No policy normalizer available. Provide --dataset-path or use a checkpoint with embedded normalizer.
```

所以结论是：

**不是一定要用 dataset；一定要有和训练一致的 normalizer。**
现在这套脚本用 dataset 来重新构造 normalizer，是因为某些 ckpt 里没有可靠内嵌 normalizer，或者为了显式覆盖到正确的训练 zarr。

你当前选中的命令没有 `--dataset-path`。如果这个 `latest.ckpt` 已经内嵌 normalizer，它可以跑；如果没有，就需要加对应训练数据路径，或者把 normalizer 固化进 checkpoint / 单独保存成部署资产。
