## assistant — 2026-08-23T07:08:43.432Z

有关系，但不是一回事。现在最大的硬件问题确实是 RGB 原始曝光不足；Gamma 只能“把暗图显示得更亮”，不能替代曝光。

曝光时间决定传感器实际收集多少光：

- 曝光从 2000 μs 增加到 5000 μs，理论进光量约增加 2.5 倍。
- 曝光更长通常能提高暗部信噪比、保留孔边缘细节。
- 代价是运动模糊、帧率限制和亮部过曝。

Gamma 是采集后的像素变换，大致为：

```text
输出像素 = 255 × (输入像素 / 255) ^ Gamma
```

- `Gamma = 1.0`：不改变。
- `Gamma < 1.0`：提亮暗部，例如当前使用的 `0.45`。
- `Gamma > 1.0`：压暗。

关键区别是：假设原始暗部只有像素值 `4`，Gamma 0.45 可以把它显示成约 `39`，但原始信号仍只有 4，噪声、量化误差和缺失的孔边缘不会凭空恢复。因此现在虽然画面“看得见了”，暗部仍有明显噪声，三孔检测也未必可靠。

你这台相机的实测情况是：

```text
网页请求曝光：5000 或 10000 μs
SDK 实际回读：2000 μs
Gamma：0.45，软件提亮成功
```

说明目前网页中的通用 `ExposureTime` 节点没有控制 WorkingMode=4 的 RGB 彩色流，很可能控制的是深度侧曝光。增益测试也没有改变 RGB 像素。

因此处理优先级应当是：

1. 找到相机真正的 RGB 专用曝光/ISP配置入口；
2. 如果该型号在 RGB-D 组合流中不开放 RGB 曝光，就增加稳定的外部照明；
3. Gamma 只用于网页观察，检测算法最好保留原始 RGB，并使用局部对比度方法处理；
4. 不应继续把 Gamma 调得很低来代替曝光，否则只是同时放大暗部噪声。

一句话：曝光增加真实光信号，Gamma 只是重新拉伸已有像素。当前 `0.45 Gamma` 解决了“看不见”，没有解决“原始图像信息不足”。
