```python

```

不是不能用，**第一版联调可以用**。坏处主要是这些：

1. **启动慢**

每次中控请求一次，你都重新启动一个 Python 进程：

```text
加载 Python
加载 torch
加载 YOLO 模型
初始化相机/参数
跑推理
退出
```

YOLO 模型如果每次都重新加载，可能几秒起步。正常做法应该是服务启动时加载一次模型，请求来了直接推理。

2. **相机资源容易冲突**

如果脚本每次都自己打开相机：

```python
cap = cv2.VideoCapture(...)
```

请求频繁时可能出现：

```text
相机被占用
设备未释放
下一次打开失败
```

HTTP 服务常驻后，最好统一管理相机连接。

3. **错误不好处理**

命令行脚本失败时，通常只是：

```text
returncode != 0
stderr 一堆文本
```

中控需要的是结构化错误：

```json
{"code": 3105, "message": "目标点识别失败", "data": null}
```

用函数可以直接 `raise` 或返回错误码；用 subprocess 还要解析文本。

4. **数据传递麻烦**

你要把参数传给脚本：

```text
motor_model
qr_content
template_id
图片路径
输出路径
```

还要从脚本拿结果：

```text
pose
confidence
error_mm
```

如果靠命令行参数、临时 JSON 文件、stdout 解析，会越来越乱。

5. **并发和超时不好控制**

中控可能短时间发多个任务。如果每个请求都拉一个新进程，容易：

```text
多个 YOLO 进程抢 GPU
多个进程抢相机
显存爆掉
速度变慢
```

函数式服务可以加锁、队列、忙碌状态，控制一次只跑一个视觉任务。

6. **状态复用不了**

YOLO 模型、相机内参、手眼矩阵、配置文件这些应该在服务启动时加载好：

model = YOLO("jm160.pt")

```text

先证明能返回 pose
先把 HTTP 格式跑通
```

result = subprocess.run(
