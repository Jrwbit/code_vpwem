我现在想在带框no hisory上添加memroy机制，设计了一个需要你来调研是否work：# 面向长程机器人操作任务的多对象时序记忆增强 Diffusion Policy

## 1. 研究背景与问题

目前使用的 Baseline 是基于 **ResNet18 + DiT 的 Diffusion Policy（DP）**，没有 VLM Head。当前策略主要依赖近期视觉观测进行动作预测，缺乏对较长历史信息的显式建模。

在长程机器人操作任务中，存在两个主要问题。

**问题一：历史信息丢失。**

机器人在执行多个连续子任务时，部分物体可能已经离开当前视野，但之前观察到的物体状态、位置或交互信息仍然对后续动作有用。

**问题二：操作目标动态变化。**

长程任务不只有一个操作对象。例如：

抓取碗 → 打开洗碗机门 → 将碗放入碗架 → 关闭洗碗机。

不同阶段需要关注的对象不同。如果 Memory 始终只围绕一个固定目标（例如碗），可能出现当前应该操作洗碗机把手，但历史记忆仍偏向碗的问题。

因此，目标不是简单地增加单目标历史帧，而是构建能够同时保存多个对象信息、支持随任务进度动态读取的对象记忆机制。

## 2. 核心研究思路

**在现有 No-History DP 中增加一个主视角的 Multi-Object Temporal Memory 分支，不修改原有的 ResNet18 + DiT 主体结构。**

整个方案分为四个模块：

### 模块 A：多对象检测与跟踪

在 DP 外部增加独立的感知模块，不需要增加 VLM Head。

首先为每个任务定义相关对象集合，例如：

- Bowl
- Dishwasher
- Door
- Handle
- Rack

离线训练和在线部署使用一致的对象类别定义及感知流程。

可采用 GroundingDINO、YOLO-World 或微调后的专用检测器，结合视频跟踪器维护对象的连续身份。

不仅检测完整物体，也允许检测可交互部件，例如 Dishwasher → Door → Handle。

对于多个同类别物体，需要额外维护 Instance ID，避免不同对象的历史特征混淆。

### 模块 B：Multi-Object Memory Bank

每个相关对象维护独立的时序记忆：

\[
\mathcal M_t=\{m_1^t,m_2^t,\ldots,m_N^t\}
\]

每个对象可以包含：

\[
m_i^t=\{f_i,b_i,c_i,v_i,\Delta t_i,H_i\}
\]

其中：

- \(f_i\)：通过 ResNet18 + ROIAlign 提取的对象视觉特征。
- \(b_i\)：当前对象的 2D Bounding Box。
- \(c_i\)：对象类别与实例身份编码。
- \(v_i\)：对象是否可见、是否曾经观察到。
- \(\Delta t_i\)：距离上次可靠观测的时间。
- \(H_i\)：对象的少量历史状态或关键帧特征。

当对象离开当前视野时，保存最后可靠的视觉特征和历史状态，但将当前 2D 框标记为无效。

初期不引入额外的深度或世界系 3D 坐标，以降低实现复杂度。需要注意，历史 2D 框不能在相机移动后直接视作当前物体位置。

### 模块 C：Object Memory Encoder

通过轻量级 Transformer 或 MLP 对多对象记忆进行编码。

核心目标不是把所有历史图像直接输入 DiT，而是将历史压缩为少量固定维度的 Object Memory Tokens：

\[
M_t\in\mathbb R^{N\times d}
\]

其中 \(N\) 为当前记忆中的对象数，\(d\) 为与策略接口兼容的特征维度。

可以先采用每个对象保存最新有效状态的简单版本，再逐步增加关键帧、运动轨迹或交互事件历史。

### 模块 D：Memory-Conditioned DiT

保留原有 DP 的当前视觉编码路径：

\[
z_t=\operatorname{ResNet18}(I_t)
\]

额外引入多对象记忆：

\[
\hat\epsilon=
\epsilon_\theta(a^{(k)},k,z_t,M_t,s_t)
\]

其中 \(s_t\) 为机器人本体状态，\(k\) 为 diffusion timestep。

Memory Tokens 通过现有的 Memory 接口或新增的 Attention 模块输入 DiT，使用标准 Action Denoising Loss 训练。

**第一版不引入 TTT，也不针对每个 Diffusion Timestep 单独设计记忆更新机制。**

Memory 在物理观测时间上更新，而不是每执行一次 diffusion 去噪就更新一次。

## 3. 如何解决操作目标动态切换？

这是相较于单目标 Memory 最重要的改进方向。

整个任务中的相关对象都可以保存在 Memory Bank 中，但在不同任务阶段，策略应当利用不同的对象信息。

例如：

| 当前阶段 | 主要相关对象 |
|---|---|
| 抓碗 | Bowl |
| 打开洗碗机 | Handle、Door |
| 放入碗 | Bowl、Rack |
| 关闭洗碗机 | Door、Handle |

初期可以让多个 Object Tokens 直接参与 DiT Attention，由策略通过动作去噪损失隐式学习对象之间的关系。

如果发现模型不能稳定进行目标切换，再增加 **Task-Progress-Aware Dynamic Memory Read**：

\[
q_t=f_\theta(z_t,s_t,h_t)
\]

\[
\alpha_i^t=
\operatorname{softmax}_i
\left(\frac{q_t^\top Km_i}{\sqrt d}\right)
\]

其中 \(h_t\) 表示近期动作或交互历史，\(\alpha_i^t\) 控制不同对象记忆的读取权重。

这样记忆可以始终保留多个对象，但不同阶段使用不同对象的信息。

需要特别验证：没有显式子任务标签时，模型是否能仅凭观测、机器人状态和交互历史学会正确切换目标。

## 4. 离线训练与在线推理如何统一？

采用同一个 Frozen Object Perception Pipeline。

**离线训练：**

演示视频 → 对象检测 → 因果跟踪 → Object Memory 更新 → Memory Tokens → DP 训练。

检测结果和跟踪结果可以预计算并缓存以提升训练效率，但对象记忆只能根据当前帧及历史帧构建，不允许使用未来帧信息。

**在线推理：**

相机图像 → 同一检测器 → 跟踪与重新检测 → Object Memory 更新 → Memory Tokens → DP 动作预测。

训练和部署需保证：

- 类别定义、Instance ID 管理与对象排序规则一致。
- Bounding Box 归一化、特征维度和缺失对象 Mask 一致。
- 在线检测失败时允许保留历史特征，但明确标记对象不可见。
- 在线使用周期性检测或低置信度触发重新检测，避免跟踪丢失。
- ResNet18 视觉特征提取方式在训练和推理中保持一致。

如果训练时使用完美 GT Box、部署时使用有误差的检测结果，会出现分布偏移。因此最好让训练阶段使用实际检测结果，并在实验中单独设置 GT 感知上界。

## 5. 计划进行的消融实验

| 实验 | 改动 | 验证的问题 |
|---|---|---|
| A0 | No-History DP | 原始性能 |
| A1 | 当前帧 Object Tokens | 对象级视觉特征是否有效 |

## 6. 需要重点评估的技术风险

**① 检测与部件识别可靠性**

通用检测器是否能准确检测机械臂需要操作的小部件，例如门把手？多对象遮挡和机器人抓取过程中，跟踪身份是否稳定？

**② 2D Memory 的空间有效性**

如果主视角相机发生移动，仅保存过去的 2D Bounding Box 是否足够？是否必须加入深度、机器人位姿或 3D 坐标？

**③ 多对象记忆是否真的有帮助**

ResNet18 当前视觉特征可能已经包含很多对象信息，需要证明历史对象状态提供了当前视觉无法获得的有效信息。

**④ 任务目标切换能力**

在没有 VLM、没有显式阶段监督的情况下，DiT 能否从动作监督中自动学习什么时候应该关注碗、什么时候应该关注把手？

**⑤ 训练与推理性能**

检测、跟踪、ROI 特征提取和记忆编码的新增延迟是否影响 DP 的实时控制频率？训练成本是否可接受？

**⑥ 与已有研究的区别**

Scene Graph DP 已经使用多对象外观及空间记忆。因此，需要明确本方案相较于已有工作的新增贡献，尤其是时序状态建模、操作目标切换以及无需 VLM Head 的轻量化集成。

## 7. 希望评估的核心问题

目前希望优先判断：

1. 该方案能否在不大幅改动 ResNet18 + DiT Baseline 的前提下实现？
2. 离线和在线使用独立检测与跟踪模块，是否能够保证输入特征分布足够一致？
3. 对于长程机械臂任务，仅保存多个对象的最新状态是否足够，还是必须保留对象级历史序列？

5. 该研究方向相较于现有 Scene Graph-Conditioned Diffusion Policy，能否形成明确、可验证的创新点？

**预期目标：** 在保留原有 Diffusion Policy 主干的基础上，通过外部对象感知、轻量级多对象时序记忆以及可学习的记忆读取机制，改善长程机器人操作中的历史信息丢失和操作对象切换问题，同时控制新增参数量、训练成本和在线推理延迟。

2. **已知 reset 问题必须进入新版本契约。** `[REDACTED long identifier].md:141` 确认 reset 用 `[frame0, frame0]` 补两帧，原 tracker 会重复推进；修复仅在隔离版本，旧 4/8 步成功率未使用修复。新 memory 必须每张真实新观测更新一次、每环境独立 reset，不能按图像内容全局去重——两张相同像素的真实连续观测仍是两个时刻。五十次 diffusion 去噪复用同一 memory 快照。

3. **“Frozen Perception”须区分检测器和对象 encoder。** 固定 detector 可以安全缓存 boxes、类别、track assignment、历史 frame index。若 `f_i` 来自继续训练的 ResNet，离线永久缓存 `f_i` 会随 encoder 更新而失配；在线又使用 EMA encoder，则不能沿用非 EMA 缓存。最小方案是固定独立 ROI encoder 并缓存其特征；另一方案缓存原图/帧引用、训练时重编码选定历史。共享 ResNet 时，历史与当前 ROI 在同一参数版本下编码，验证 EMA 重编码，不能只冻结 detector 就宣称特征一致。随机采样训练时不能继承上一个无关 batch 的有状态记忆。

4. **最新状态足以解决部分遮挡，不足以保证阶段可识别。** “碗最后见于左侧”可由最新可靠状态保存；“某次开门是否完成”“现在是初次接近还是失败重试”可能要求事件或历史。当两段历史压缩后产生相同 `(当前观测, 本体状态, 任务ID, 最新对象bank)`，但正确动作不同，增加读 Attention 无法恢复已被丢弃的信息。A2 应作为强基线；A3 只添加可验证的历史信息，如每对象少量历史状态、夹爪实际执行动作与交互事件。`h_t` 必须来自已经执行的动作，不能使用未执行的预测动作段尾部或未来演示动作。全局 task ID 已存在，应进入读 query；不能把“无阶段标签”写成“无任务条件”。

5. **多对象 Attention 已是动态读取，显式 reader 是待验证优化。** DiT action query 对 memory 的 cross-attention 本就按当前条件和去噪状态改变权重。新增 `q_t` 的价值要具体定义为引入此前没有的进度证据、减少计算或改善稳定性；若只是另一层 attention，不能直接视为独立创新。展示 attention 热图也不能证明成功的阶段选择。建议默认软读取完整对象集合，避免过早 hard top-1；失败时先区分“对象根本未检测到”“记忆错误”“阶段不可识别”“已有信息未利用”。
