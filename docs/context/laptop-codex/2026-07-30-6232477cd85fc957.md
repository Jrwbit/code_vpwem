有，而且可以做到大多数卡死自动恢复，不需要人工 `kill PID`，浏览器前端也不必退出。

目前项目的问题是：网页/API 服务和海康 SDK 采集位于同一个 Python 进程；相机采集虽然用了线程，但 SDK 如果卡在原生函数里，Python 无法可靠终止该线程。因此现有 `/camera/stop`、`/camera/start` 只能处理普通无帧，处理不了 SDK 真卡死。相关实现见 [hik_fast_rgb_service.py](/[REDACTED long identifier].py:194) 和 [hik_fast_rgb_service.py](/[REDACTED long identifier].py:334)。

建议做成分级自动恢复：

1. 连续 3～5 秒没有新帧：调用 `MV3D_RGBD_ClearDataBuffer()`。
2. 仍未恢复：执行 SDK 的 `Stop → CloseDevice → 重新枚举 → OpenDevice → Start`。
3. SDK 调用本身卡住：只杀并重启“相机采集子进程”，网页/API 主进程继续运行。
4. 相机固件彻底失联：自动重置设备供电。
   - 网口 PoE 相机：通过可管理 PoE 交换机自动 cycle 对应端口。
   - 独立 24V 供电：增加网络继电器或 USB 继电器。
   - USB 相机：先尝试 USB device reset 或解绑/重绑驱动，最后才切 USB 口电源。
5. 给相机子进程和主服务增加 `systemd` 守护，异常退出后自动拉起。

其中第 3 步最关键：把海康 SDK 隔离到独立进程后，即使 C SDK 永久卡住，也只需 watchdog 对相机进程发送 `SIGTERM`，超时后 `SIGKILL` 并重启；网页、任务状态和机器人安全控制不会一起被杀。当前脚本虽然能发现整个服务不响应并自动杀进程，但粒度还是整个服务，见 [hik_rgb_fast.sh](/[REDACTED long identifier].sh:35)。
