## assistant — 2026-07-16T09:27:49.976Z

原因主要在于：`ImageMode` 控制“输出什么数据”，并不等于控制“哪些硬件上电”。

这台 `MV-DLS300P-04T` 是一体化 RGB-D 相机。打开设备后，固件会启动内部深度工作流程，投射器也由这个流程统一管理。即使设置：

```text
ImageMode=8
```

也只是让 SDK 输出彩色帧、减少深度数据传输和处理，并没有命令深度引擎停机。

`0x80060007` 在海康 SDK 中的准确含义是：

```text
MV3D_RGBD_E_PRECONDITION
前置条件有误，或运行环境已发生变化
```

定义见 [Mv3dRgbdDefine.h](/[REDACTED long identifier].h:87)。

你这里已经在相机开始采集前尝试写入 `LaserEnable=false`，仍然返回该错误，因此基本可以排除“采集中不允许修改”。更符合实际的原因是：

- SDK 是多个 RGB-D 型号共用的，所以提供了 `LaserEnable` 节点；
- 但当前 DLS300P 的固件/工作模式没有开放这个节点的独立写权限；
- 投射器状态与深度工作流程绑定，不能由用户单独关闭；
- `OpenDevice()` 启动的工作环境不满足修改该节点的固件条件。

因此它不是 Linux 或代码语法问题，也不是把设置顺序简单调整一下就一定能解决，而是当前型号及固件的控制限制。

如果目的是降低网络和 CPU 负载，现在的 `ImageMode=8` 已经有效；如果目的是让激光真正熄灭，例如避免干扰其他相机或出于安全考虑，则需要：

1. 向海康确认该型号是否有支持独立关闭投射器的新固件或专用工作模式；
2. 若固件不支持，改用独立 RGB 相机，或者在硬件层面遮挡/断开投射器——后两者应先经厂家确认，避免损坏设备。

简而言之：**你关闭的是深度数据输出，不是深度硬件；激光开关被固件锁在深度工作流程里。**
