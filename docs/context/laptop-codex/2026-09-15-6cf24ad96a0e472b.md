需要保留，但不应该把整段复盘原样塞进“聊天记忆”。对于机械臂控制，最好把知识分成可审查、可执行的项目文件；聊天记忆只负责偏好和背景提醒。:codex-annotation{index="1"}

推荐分成四层：

1. `AGENTS.md`：必须遵守的长期规则

Codex 在项目中工作前会读取 `AGENTS.md`，适合保存每次任务都必须执行的规则。[OpenAI 官方说明](https://learn.chatgpt.[REDACTED long identifier])

例如加入：

```md
## 机械臂任务规则

- 运动前先根据双视图建立完整的装配/拆解约束关系。
- 力传感器没有校准，禁止读取或用于决策。
- 空中无障碍移动默认采用 60–80 mm 步长、80 mm/s。
- 接近物体或桌面最后 10–25 mm 时减速并使用视觉确认。
- 模型上下文只保留最近 3 个关键视觉步骤。
- 完整位姿、图片和反馈写入运行日志，不放入对话上下文。
- 每个物体原则上只在对准、夹紧、提离、放下四个节点确认。
- 每次开始任务先拍摄两路最新图像，不假设桌面状态与上次相同。
```

其中速度应当是“满足安全间隙时的默认值”，不能写成无条件强制值。

2. `config/robot_cell.yaml`：标定和硬件事实

这些不是语言记忆，而是控制程序必须读取的参数：

```yaml
robot:
  ip: 192.168.10.12
  tcp_source: fingertip_center
  safe_workspace: ...
  speed:
    free_space_mm_s: 80
    near_object_mm_s: 20

cameras:
  overhead:
    serial: "153222071023"
    T_camera_to_base: ...
  side:
    serial: "213622078851"
    T_camera_to_base: ...

sensors:
  force:
    calibrated: false
    usable_for_control: false

scene:
  table_plane: ...
  base_pose: ...
```

相机外参、指尖 TCP、桌面平面等必须通过标定获得，不能把这次试探得到的近似值冒充标定结果。

3. `state/latest_scene.json`：当前物理状态

用于保存容易变化的事实：

```json
{
  "verified_at": "...",
  "gripper": "open_empty",
  "robot_stationary": true,
  "objects": {
    "green": "left_table",
    "red_upper": "front_table",
    "blue_upper": "right_table",
    "blue_long": "yellow_base"
  },
  "confidence": "visual_verified",
  "latest_images": ["overhead.jpg", "side.jpg"]
}
```

每次新任务开始仍需重新拍照核对，因为人可能移动过物体。

4. `runs/`：经验和完整历史

保留：

- 全部原始图片
- 位姿和夹爪日志
- 动作结果
- 成功或失败原因
- 最终动画
- 一份简短任务总结

后续模型只读取任务总结和最近三个关键帧；只有发生异常时才回查完整历史。

聊天“记忆”可以辅助跨会话记住“用户喜欢大步移动”“不使用未校准力传感器”等信息，但不应成为控制规则的唯一来源。官方文档也建议把必需的团队规则放在 `AGENTS.md` 或受版本控制的文档中，把 Memories 当作辅助召回层。[OpenAI Memories 文档](https://learn.chatgpt.com/docs/customization/memories)

本地 Codex 的 Memories 默认可能未开启，可以在设置中启用，或配置：

```toml
[features]
memories = true

[memories]
generate_memories = true
use_memories = true
```

交互界面也可以用 `/memories` 管理。它是后台异步生成的，未必在一次对话结束后立即更新，因此不适合承载“禁用力传感器”这类必须可靠执行的规则。

以后每次任务的启动顺序应固定为：

```text
读取 AGENTS.md
→ 读取硬件标定配置
→ 获取两路最新图像
→ 核对 latest_scene
→ 建立完整装配依赖图
→ 一次性规划抓取顺序
→ 执行大步空中运动和小范围精确接近
→ 更新场景状态和任务总结
```

这样即使换一个新对话，只要仍在这个项目目录，关键知识也能稳定保留并被重新使用。
