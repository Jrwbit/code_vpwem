## 根因及算法修改

此前失败路线 `59d35730737d4602bcb12c6ed560d99a` 的原始输入显示：腰部相对名义工作腰姿的J4差为0.036765237°，左臂相对名义home的J1差约0.037978507°。腰部恢复逻辑在0.1°到位容差内选择保持实际反馈，而GPU／CPU后续路线从名义工作腰姿及名义home重新起算；两套边界来源产生了计划路点跳变。此前修正左臂home连接只能解决其中一部分，并没有统一腰部及后续求解的起点。

新增 `corridor_worker.planning_start()`，在任何恢复、复用、GPU或CPU求解前一次性选择整条检测路线的起点。检测模式下，腰部在已有0.1°到位容差内、左臂在已有1°home到位范围内，均使用实际反馈作为共同锚点；后续求解、碰撞模型、导出及原路返回全部沿用这份起点。超出范围仍生成受检查的恢复段。复位模式继续使用保存的名义home和目标腰姿，不改写保存的工位参考。

功能性的接近、插入、撤离等分段继续保留；修复的是各分段重复从不同的“home”起算，而不是取消有实际作用的分段或碰撞检查。`require_continuous_segments()` 的1e-8 rad计划接缝条件保持不变，该条件检查计划路点，不要求实物反馈达到这种精度。GPU输出终点名称同时改为“名义检测对位”，避免把名称当作新的实物验收记录。
