# 2026-10-21 当前JL132相对UR方案的差异及记录更正

本次只读比较原UR源码 `/home/wjr/code/r435`、当前洛石统一源码及前一轮已核实的现场配置，没有执行运动或修改产品参数。

- −90°是当前 `flange_T_tcp=Rz(-90°)`，平移为0，属于整套工具的共用安装变换，不是JL132专属补偿；100、132、160都会经过它。JL132自身TCP到工装的+120°仍保留，合成法兰到工装方向为+30°。不能把两层角度相互替换，也不能说与UR相比一定多转了−90°：尚无UR成功时活动TCP的现场快照作逐项对照。
- JL132额外高度补偿从原配置−22 mm变为0；工装原始矩阵中的Z=29.23 mm仍保留，没有把实际工具高度清零。100的−18 mm不因132修改而自动取消。
- JL132当前没有额外盒中心XYZ平移；160（JM160）另保留盒局部X向−2 mm。未找到对JL132主动添加局部Y偏移的目标计算。
- 工装原始矩阵沿用UR表。UR目标为 `Base_T_TCP = Base_T_box × shift × inverse(TCP_T_fixture)`；洛石再乘 `inverse(flange_T_tcp)`得到法兰目标。同一物理坐标定义下两式对应，属于TCP指令与法兰指令的差异，不表示多补偿一次。
- UR使用对应UR基座的手眼及固定基座；洛石当前15组会话来自右臂持板，增加右臂标定到左臂基座转换，以及标定腰姿到工作腰姿的转换。安装几何与外参不同，不能把UR成功时的精度直接迁移为洛石已验收。
- UR代码发送movel笛卡尔目标，由控制器处理逆解；洛石完整路线经软件运动学和碰撞规划，导出关节目标后用MoveAbsJ执行。洛石多了软件模型与真实控制器几何一致性的依赖；已修正过模型和起点接缝，不能继续当成未修复问题，也不能据此认定剩余误差必然来自模型。
- UR保留原来的过渡高度及动作参数；洛石使用当前工位home、GPU中转路线、关节执行参数30／插入20，本轮在检测位停留20秒。速度数值与UR的m/s等参数不能直接一比一比较。
