# 2026-10-21 JL100与JM160检测支持核对

在JL132完成新一轮运动循环后，用户询问100、160能否检测。本次仅只读核对代码、现场配置及历史仿真，没有切换型号、触发采集或移动机械臂。

结论：两者的软件配置和型号分支已接入，可以复用当前采集、手眼转换、完整路径规划及执行流程，具备开展实机验证的基础；当前没有证据确认两者在本工位、新15组标定和当前安装条件下已经完成实机检测。132的成功不能代替另两型号的目标姿态、路径及实际对位验证，也不能据此判断100比160更容易。

现场 `config/rokae_site.json` 包含JL100、JL132、JM160三个 `tcp_T_objects`；型号映射为100→JL100、132→JL132、160→JM160。当前选择仍为JL132，视觉参数product_type仍为132。

JL100保留旧高度补偿−18 mm；JM160保留盒中心局部X向−2 mm补偿，未配置专属高度补偿时按代码默认0计算。132当前高度补偿为0。需核对另两型号这些既有补偿的实际适用性，不能直接复制132的高度结果或将其清零。

`robot/rokae_hover.py` 按当前型号检查所选工装一致性，并组合工装矩阵、高度及中心补偿生成完整末端目标。不同工装的偏心和方向会改变所需关节姿态，因此不能直接复用132的关节路线。132本次验证过的接缝修复与连续路线速度监测改动属于共用执行逻辑，另两型号可受益，但不保证新路线可达或执行必然成功。

历史三工装布局研究曾找到非接触循环，但采用假设工位、相机额外抬高120 mm及统一盒体包络，不能作为当前现场100／160已通过的依据。参见 `docs/jinlong_left_layout_study_20261017.md`。

下一步应每种真实电机分别上台，确认型号与工装匹配后重新采图、生成去返完整路线并复核，再从悬停／接近检查实际横向、方向及高度误差，最后验证检测位及返回。若相机和安装关系保持不变，不因电机型号变化本身而要求重新做手眼标定；每种工装自身的几何补偿仍应分别核对。电气检测仍取决于电测系统接入，当前132成功记录只证明运动循环完成。
