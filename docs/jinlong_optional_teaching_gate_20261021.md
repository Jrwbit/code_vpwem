## 实现依据及边界

原位置为统一源码仓库 `vision/app/hk_pointcloud_registration/robot/rokae_trajectory.py` 的 `start_trajectory()`。在路线已生成并调用 `_trajectory_binding()` 后，它读取 `site.teaching_evidence`，比较几何摘要、工装型号、标定SHA、高度补偿及固定的-90°安装矩阵，否则抛出“本工装／标定尚无匹配的示教对位记录”。这段逻辑没有读取实测偏差、做碰撞判断或计算控制器限位；它要求历史文件字段匹配。当前实际阻塞项仅为旧记录的标定SHA不匹配15组新标定。

| 逻辑 | 实际作用及本次处理 |
| --- | --- |
| 历史记录匹配 | 删除后端启动门槛和前端禁用条件；匹配状态继续如实展示，明确不阻断运行 |
| 工装与工具几何 | 路线生成仍经 `corridor_worker.configure_geometry()` 校验支持的工具变换、同步旋转碰撞几何；不再额外用旧记录块硬编码-90°限定启动 |
| 当前路线绑定 | `_trajectory_binding()` 仍核对当前工位修订、活动标定SHA、控制器运动学摘要，变化则要求重新求路线 |
| 碰撞与目标 | `_plan_trajectory()` 仍要求碰撞检查回执；工作器对导出的关节线段用当前场景检查碰撞、目标与控制器限位余量。GPU提案仍经CPU复核 |
| 现场确认及停稳 | `RokaeOperator._authorization()` 仍要求本机会话及现场监护、路径、当前报警确认；启动仍需 `power_workflow()` 下电停稳预检 |
| HMI及原生设备执行 | `plan_runner.py` 继续校验有效计划、实时起点、持有部件、软限位、速度、停止锁定和心跳；`xcore_motion.cpp` 的受保护限位、速度、碰撞反馈和退出机制未修改 |

示教保存功能仍校验其自身的参考和实测填写，并维持配置历史备份，但是否选择保存记录不再决定路线能否启动。保存后导致旧路线失效的既有配置修订规则保持。没有把独立定位精度验收设为通过，也没有以本次软件验证宣称实物误差改善。
