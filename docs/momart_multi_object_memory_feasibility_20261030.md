# MoMaRT 带框 No-History：多对象时序记忆可行性与创新性审查

日期：2026-10-30（北京时间）。范围：用户提出的 ResNet18＋Diffusion Transformer、多对象检测跟踪、对象记忆及动态读取方案。结论依据本地源码、截至10月30日的既有审计和一手论文；本轮没有实现新策略、训练、启动评测或读取服务器实时运行状态。文中建议配置、预算与判据均待实验验证。

飞书报告：https://feishu.cn/docx/OWlqdkloNoj0Avx6U0scFCymnjf

**结论：值得做一个受控原型，工程上可以保留现有主干，但目前不能保证提升成功率；“多对象＋最新状态记忆＋Attention＋无VLM Head”不足以单独构成明确创新。** 最有价值的问题是：在相同感知、历史范围与资源预算下，少量对象交互历史能否消除最新状态无法区分的任务阶段，并改善遮挡后的操作对象切换。

| 用户的核心问题 | 判断 | 决定性条件 |
|---|---|---|
| 不大改 ResNet18＋DiT 能否实现？ | 可以，已有 memory 条件槽位 | 要增加对象编码、mask、训练数据和在线状态接口；不是只更换一个 memory 类 |
| 同一个冻结感知管线能否保证离线在线一致？ | 能减少处理差异，不能保证输入分布相同 | 取帧、reset、跟踪关联、增广、缓存权重版本必须一致；策略偏离示范仍造成分布偏移 |
| 最新状态是否足够？ | 足以做对象持久性基线，未必足以推断进度 | 最新可见外观不能普遍表示交互顺序、失败重试或已完成事件；不一定需要完整历史序列 |
| 普通 Attention 是否足够？ | 应当先用，是有依据的首版 | 它本身已有动态读取；额外 reader 应证明提供了什么新信息或计算收益 |
| 相较 Scene Graph DP 是否新？ | A2 重叠很强，A3/A4 也有近邻 | 聚焦可证伪的阶段歧义、低成本时序压缩与受控泛化；不能预先声称首次或效果成立 |

**先对齐真实基线**

这里的 No-History 指策略没有长期历史条件，不是完全只看一帧，也不表示外部 tracker 没有状态。当前带框版仅在最近两帧的主 RGB 上画固定红碗框，提示为 `a red bowl.`；它没有长期 token，也没有独立 ROI／位置 token。另一个“带框＋坐标/ROI”版本增加的是最新帧红碗的两个 token，仍不属于长期记忆。

实际主观测还包括腕部 RGB、两路深度、scan 和 proprio。四路视觉各512维，加 scan64、proprio10，经2122→256→256融合，再加任务 embedding，得到 `[B,2,256]`。因此，本研究的“2D-only”只能指新增对象记忆不引入世界系3D，不能把整个既有策略称为 RGB-only。无显式阶段标签也不等于无任务条件：现有 task ID 应继续保留。

动作骨干精确名称是 `LongMemChiTransformerPTP`，256维、8层、4头；可泛称 diffusion Transformer，但不应与仓库另一个 `DiT1d` 混称。常用设置预测9步10维动作、执行索引1起的8步、50步DDPM；执行4步的实验是另一观测频率协议。源码和归档定位：

- `configs/dp/momart/fair_history_multitask/base.yaml:19`；`pipelines/fair_history_momart_multitask.py:118`。
- `cleandiffuser/nn_condition/multi_image_condition.py:492`、`:600`；`cleandiffuser/nn_condition/momart_history_condition.py:13`。
- [实际架构与框/ROI审计](https://feishu.cn/docx/ACTLdfMHCoVVsyxqhNycPrq1nm4)、[新1M训练记录](https://feishu.cn/docx/SlC8dHdpcolDPixTeyucMmeWnug)。本地源分别为 `momart_boxed_token_audit_20261028.md`、`momart_boxed_nohistory_bs64_1m_20261029.md`；后者10月30日进度是已有记录，不是本轮实时查询。

最新[总成绩汇总](https://feishu.cn/docx/A4mVdzwCZovWOlxKxXNci1fynze)已有同评测seed的150k无框61.33%、带框59.33%、带框＋坐标/ROI53.33%；250k无框62.33%、带框64.67%。预算链、学习率和配置限制详见原报告。这些历史成绩既不证明 memory 有效，也不证明多对象 memory 会失败；尤其不能用不同预算的1M成绩直接归因。固定碗与阶段对象不匹配及ROI敏感性仍是[待验证机制](https://feishu.cn/docx/GU6adqL59oGoNqxyCMOcsy7rn94)。本地源为 `momart_total_success_20261029.md` 和 `momart_token_diagnosis_20261029.md`。

最关键的对照应是 **Scene Graph风格的最新状态对象记忆**：不能通过删掉3D或改用ResNet，就把已有消融当新方法。论文里描述的图并不要求复杂的显式关系边；“我用平坦对象token，它用图”也不足以自动建立区别。这里对后续贡献的建议是研究推论，不是论文已验证的结论。

**首版应如何接入**

建议保留当前带框全景、多模态融合、任务embedding和动作主干，新增如下独立流程：

```text
当前主相机原图 → 冻结检测/因果跟踪 → 按实例更新对象bank
                                     ↓
                      对象特征 + 可见性/时间/类别 → 轻量MLP
                                     ↓
                     [B,Nmax,256] + 有效性/时间mask
                                     ↓
当前两帧多模态条件 ─────────────→ 现有动作Transformer cross-attention
                                     ↓
                             50步去噪 → 执行动作块
```

`Nmax=8`、每实例1个token、256维、首版不加对象Transformer，是可起步的预算示例，不是经过数据验证的最优值。先统计十配置内类别、每回合累计需记忆实例以及未淘汰轨迹峰值，后者必须包含离屏对象；碗、门/把手、篮架/拉手及任务需要的柜体对象应按真实数据覆盖，不能只照洗碗机例子硬编码。超过容量时的保留／淘汰规则须一致记录。父物体、门、把手允许同时存在，但应明确 `parent_id/part_role`；检测置信度不能当任务相关性分数。

感知原型优先扩展现有GroundingDINO管线的对象词表，先确认多类别输出和实例关联能力。逐类别抽查部件召回、框质量、ID切换、遮挡后重新关联以及端到端耗时，不能只看整图平均检测指标。若小把手覆盖不足或时延不满足，再比较领域微调检测器；目前没有本环境实测依据断言GroundingDINO、YOLO-World或专用检测器哪一个最好。

推荐对象状态为：

```text
class_id, episode-local track_id, parent/part_role,
source_frame, last_seen_timestamp, feature_or_frame_reference,
seen, visible, bbox_valid, current_bbox, age, confidence,
history_references (A3 only)
```

`track_id`是回合内关联键，不是具有跨回合语义的整数类别。类别／部件角色可以学习embedding；槽位顺序应稳定，不能每次按置信度重新排列历史。若检验排列鲁棒性，应对对象及其完整历史、mask一起置换。遮挡后重新出现时需验证身份关联，不应把同类新对象静默合并到旧轨迹。

| 对象状态 | 当前2D框 | 历史外观 | 注意力行为 |
|---|---|---|---|
| 从未观察到／空槽 | 无效 | 无 | padding mask屏蔽 |
| 当前可靠可见 | 有效 | 更新 | 可读取 |
| 曾见、目前不可见 | 无效；旧框只可另存为历史坐标 | 保留最后可靠观测 | 仍可读取，输入age和不可见标志 |
| 跟踪身份／质量不确定 | 按质量标注 | 不轻易覆盖可靠旧状态 | 显式提供不确定性；必要时新建轨迹 |

是否有当前框与是否有有效记忆必须分开。不能因物体不可见就屏蔽整个token，也不能把一个全零框默认解释成图像左上角。

**已有接口能够复用，但有四处必须实改**

1. `longmem_chitransformerptp.py:171` 已接受 `[B,Tm,256]` memory，现有 `mem_emb` 和 cross-attention可复用；新增真正的对象级 `memory_key_padding_mask`。仅置零会经过bias、位置embedding和MLP重新变为非零，不能替代mask。
2. 原PTP允许所有旧history memory对所有动作位置可见（同文件`:149`），因为旧memory来自近期窗口以前。最新bank已经读到当前帧，最简单做法是**动作位置0不得读最新bank，位置1及之后允许读取**，继续沿用既有观测时间约束。若token间先混合，时间权限必须按最晚输入信息计算。若打开条件Transformer，还要阻止它先把当前信息混进较早条件token，再绕过decoder mask。
3. `longmem_ddpm.py:287` 的字典memory默认经全景观测编码器；对象bank要有专用路径。`:751`、`:765` 的显式 `memory_cfg` 路径受 `nn_memory` 是否非空约束，不能在 No-History 配置下直接传对象张量就假定生效。`:616` 的reset也不自动清理新增tracker与每环境bank。
4. `Tm`变化会改变条件位置embedding和mask尺寸。从旧模型初始化时，要将原来的 `[diffusion,obs0,obs1]` 行映射到新序列对应位置，重建mask；`strict=False`并不会解决同名参数尺寸不匹配。加入token还会改变attention归一化，不能保证初始动作和旧权重逐值相同。

首版保留逐token条件MLP即可。仓库还有 `gated` 和 `control_indexed` 读取模式（`longmem_chitransformerptp.py:93`起），但它们针对原全局memory，不等于已经实现了对象级进度读写或空槽mask。

**视觉特征与缓存是必须先选清的工程路线**

当前ResNet输出512维池化向量，不能对它直接做ROIAlign；需要池化前的二维特征。75×100输入经过stride32末层约为3×4网格，小把手细节可能已经丢失。应先统计部件在原图中的像素大小，考虑layer2/3的较高分辨率特征；提高ROIAlign输出尺寸不会恢复原本不存在的信息。既有ROI版是原图紧裁后缩放到64×64另过ResNet，不是ROIAlign。

带框主路径还有一个实际选择：共享画框图的特征图时，对象特征也含画框影响；要求对象分支来自原图、而全景仍画框，就通常要额外编码原图。ROIAlign在一张特征图上提取多个对象可以避免每个对象各跑一遍ResNet，但不能把额外原图前向的成本省略不报。

| 路线 | 训练与缓存约定 | 收益和代价 |
|---|---|---|
| 共享可训练ResNet | 离线只缓存框、因果关联及历史帧引用；训练按当前权重重编码所选历史原图，再ROIAlign | 不新增完整backbone权重；历史重编码增加训练计算，共享梯度会改变全景特征 |
| 独立冻结对象ResNet | 从指定已有checkpoint或明确预训练权重初始化，固定预处理和权重哈希；可缓存对象特征 | 首版更容易对齐与调试；增加一套存储和在线图像编码，不能只看新增可训练参数 |

不建议为方便缓存而冻结整个原策略视觉主干，这会改变基线训练设置。源码 `get_resnet(..., weights=None)` 默认不加载预训练（`multi_image_condition.py:49`），因此不能新建后直接冻结随机ResNet。冻结检测器也不意味着特征编码器冻结。主干可训练时，永久使用旧ResNet特征缓存会产生版本漂移；推理若用EMA，缓存必须来自同一EMA／冻结对象编码器，且切换checkpoint时清空bank。

**离线与在线统一：定义一条因果观测流**

同管线是必要条件，不能保证部署状态分布与示范分布相等。应同时固定检测模型、prompt、阈值、tracker参数、重检测触发、输入图像处理、帧时间戳和执行块长度，并保存版本manifest。评测不同动作频率或感知频率时，将其作为新协议，不混用旧缓存。

当前归档在线取帧为 `0,0,7,8,15,16,…`：每次重规划才把最近两帧送给tracker。训练若逐帧处理完整视频，会拥有在线未接收的观测和不同跟踪状态。reset重复frame0曾推进两次tracker，已在隔离版本修复，既有成绩未统一切换；详见[时序与reset审计](https://feishu.cn/docx/ACTLdfMHCoVVsyxqhNycPrq1nm4)。新实验应统一修复版本并重跑相关基线。

具体契约如下：

- 用 `(episode_id, env_id, sensor_step, timestamp)` 标识观测；补帧只复用结果，真实新帧即使像素相同也正常推进，不能全局按图像去重。
- `age`由传感器时间或模拟环境时间差计算；不是GPU墙钟耗时、tracker调用次数，也不是diffusion步数。
- 检测、跟踪、bank更新只看截至当前可用的观测。禁止双向跟踪、未来帧平滑、依据最终成功状态选择关键帧或用未来信息回填此前不可见对象。
- 从episode起点按部署可见帧重放，保存每个训练anchor的last-seen/关键帧引用。随机训练batch读取自己的因果快照，不能继承上个无关batch的bank；截取片段冷启动也不能冒充完整历史。
- 若训练采样不同重规划相位或执行块长度，分别匹配对应可见帧序列。若改为持续异步感知，必须在部署中真实处理这些帧并计入延迟、丢帧和观测年龄；训练也模拟对应可用性。
- 增广后的框必须对应ROIAlign使用的那张特征图。原图坐标与随机裁剪坐标要明确区分；不沿用原RGB、深度、相邻帧分别抽裁剪窗口却声称完全空间对齐的描述。
- 真实检测结果用于主训练协议，误差增强覆盖漏检、抖动、伪框与短期关联错误；参数只在训练/验证集调整。GT感知只作单列诊断上界，且仍遵守因果可见性，不能给未曾看到的隐藏对象真实状态。
- 同一观测anchor在全部50次去噪中使用同一bank快照。读取权重随动作噪声或diffusion timestep变化是正常条件计算，不等于写入记忆；不需要TTT。

原全局历史sampler会分段随机抽帧并补齐历史（`robomimic_dataset_utils.py:582`、`:887`），不能直接拿它重建有状态的实例跟踪。对象缓存与状态协议是本项目主要工作量之一。

**最新状态、历史序列与阶段切换应怎样判断**

每对象最新可靠观测可以回答“这个对象曾出现过、最后是什么样”，适合短遮挡和对象持久性。它不必然回答“做过什么、成功过几次、应该继续还是重试”。例如已经抓住又放回的碗，可能与从未抓过的碗有相似最新外观；把手曾被拉动并不证明门已打开。夹爪闭合也不是抓取成功标签。

设两个历史在压缩后产生相同的 `(当前观测, 本体状态, task ID, 最新对象bank)`，却要求不同的下一动作。任何只读取这些变量的网络都无法可靠区分它们；再加一层attention也不能恢复已经删除的信息。这是可识别性限制，而不是“Transformer不够强”。反过来，如果当前观测已充分揭示门、碗与篮架状态，没有理由保证额外历史一定提高成绩。

因此不需要直接保留完整对象视频。推荐A3先比较每对象2–4条带相对时间的因果状态/关键帧，聚合后仍输出一个256维对象token；候选采样包含最近状态和此前的显著变化或交互前状态，所有规则只看前缀。也可比较对象级GRU压缩状态：充分的递归状态可能不需要显式序列，但不能把“只覆盖最新外观”与“已融合历史的隐状态”混为一谈。

若还要加入 `h_t`，它应来自过去实际执行的动作、夹爪反馈和已观测交互结果；不能使用未执行的预测动作块尾部或未来专家动作。它应覆盖任务需要的历史时间尺度，近期几步动作并不自动等价于长程进度。可加一个很小的全局进度状态，与对象记忆互补；必须通过等输入消融区分它与reader的贡献。

普通DiT cross-attention本来就会动态读取多个对象，适合先验证；放碗时还同时需要碗与篮架，不能预先假设每阶段只有一个目标。显式reader若把所有对象softmax后压成一个向量，可能反而损失多个对象的角色关系。后续需要时优先比较少量多头query或带残差的软读取，并保留对象集合。query应包括现有task条件；若A4新增了进度历史，要先让A3获得同一份信息，才能把收益归因于读取方式。attention热图只能辅助观察，不能单独证明任务切换成功。

**2D记忆的适用范围**

将离视野对象的当前框标无效是正确做法，但它只避免错误坐标，并没有恢复当前空间位置。移动相机下，历史框不是当前目标位置；即使相机固定，被机器人拿着或被别的物体推动的对象也可能移动。需要分别检验“静态对象被遮挡”“相机移动”“对象离屏后继续移动”。

第一版可以把2D记忆用于身份、外观和交互状态，在对象重新进入视野后用当前观测定位。若任务要求相机移动后仍对不可见位置直接精确操作，仅2D框＋age通常缺少足够几何信息；应另测相机位姿/本体运动补偿、深度或世界系坐标。这是任务条件下的升级理由，不是首版必须堆入3D的结论。3D最后位置对隐藏后自主移动的对象同样会过时，需要状态估计与不确定性。

**建议的最小实验矩阵**

所有主对照固定原带框全景、数据划分、task embedding、初始化来源、更新数、有效batch、学习率计划、动作执行长度、扩散采样配置与评测初态。共享参数尽量同源初始化，不能只固定seed就假定模块新增后随机数轨迹仍相同。

| 实验 | 唯一主要变化 | 要回答的问题 |
|---|---|---|
| A0 | 带框No-History，当前真实基线 | 原方案水平；另列无框No-History作为背景对照 |
| A1 | 仅输入当前可靠可见对象；缺失槽屏蔽，不提供历史外观、事件或last-seen状态 | 多对象覆盖／表示的作用；仍用同一tracker关联与检测流程 |
| A2 | A1＋每对象最新可靠状态跨帧保留 | 持久记忆是否优于同架构当前对象 |
| A3 | 每对象少量历史／事件压缩，输出token数不变 | 历史内容与顺序是否优于最新快照 |
| A4 | A3同样信息＋显式动态reader | reader本身是否有额外价值 |
| B1 | 同历史范围的全景FIFO／帧记忆或小GRU | 收益来自对象组织还是仅多给历史 |
| B2 | 同编码器/感知的Scene Graph风格latest-state对象基线 | 相对最接近机制是否有增益；自适配版不能冒充官方完整复现 |
| B3 | 同输入、相近预算的GMP风格门控／查询 | 显式读取是否优于已有简单设计；近似版须明确标记 |

A2/A3均保持相同对象数上限、输出token数量和读取主干；为A3增加时序encoder时，补等容量latest-only控制。A3不应同时增加历史、token数和参数再把总收益全部归因于时序。首轮无需运行整张矩阵：先感知审计与A0/A1/A2，确认历史价值后展开A3，再决定A4。A1未优于A0不意味着A2必然无效，但A1明显退化应先排查表示与感知。

主指标是同协议完整任务总成功率。按本轮研究问题附加阶段成功率、目标切换失败、遮挡间隔分组和时延诊断；不以阶段分数替代完整成功。阶段标签可仅供评测分析，不能默默送入正式模型。切换失败应结合接触对象、状态变化和后续动作定义，不能按attention最大值判断。

关键诊断包括：

- 构造近期观测接近、但历史状态／身份不同且下一动作不同的任务对；并保留当前观测足够的控制任务。变更等待时长、操作顺序和失败重试，避免模型只学固定episode时钟。
- 同类别多实例、目标交叉／遮挡后重现、门与篮架部件、小框漏检、相机移动、离屏对象移动，分别记录检测、关联和控制错误。
- 固定模型下做memory reset、在类别/年龄/可见性匹配条件下替换历史、打乱事件顺序。它们属于分布外干预诊断，须与重新训练的A1/A2/A3对照共同解释；不能单独用“清空后降分”证明正确记忆。
- GT感知／oracle阶段只作为单列上界诊断；完整第三方基线与自适配同主干对照分别标注，避免把感知、3D或VLM信息优势当算法收益。
- 正式主结论至少覆盖多个训练seed（建议3个起），配相同评测初态和独立rollout随机源，报告置信区间或训练seed差异。同seed确定性重复不计作独立样本；不同方法消耗随机数不同也要避免破坏初态配对。

**成本、必要验证与继续推进判据**

感知耗时很可能比8个小对象token的MLP更重要，但没有实测前不能报毫秒数或承诺控制频率。同步路径应分项测量检测／跟踪、特征提取、memory编码、全部去噪、数据传输与动作调度；同时给端到端p50/p95/p99、丢帧及排队时的观测年龄。异步路径不能简单相加组件耗时，须测实际关键路径。实时约束来自实际动作块时长与控制deadline，不应只拿“每步memory耗时”宣称可实时。

报告新增可训练参数、总模型常驻内存、GPU峰值、每训练更新耗时、总GPU小时及离线缓存预处理成本。以8对象×256维float32为例，最终对象token仅8KiB；每对象3条同维特征约24KiB，但这些数字不包含ResNet、检测器、原图、KV及训练激活，不能用来代表整套系统很轻。读memory的cross-attention会在每个去噪步运行，bank和特征不应重复更新。

开始闭环实验前，必要检查限于：

1. 同一观测序列的离线前缀重放与在线逐步bank逐字段一致，随机访问anchor不串状态；更改未来帧不影响此前bank。
2. 空槽、遮挡后保留、身份重现、容量上限、跨episode reset与多环境隔离正确。
3. ROI与特征图坐标一致；RGB/框增广同步；冻结缓存或可训练/EMA重编码版本正确。
4. 动作位置0无法读取最新bank，空槽真正被attention屏蔽，50步去噪前后bank状态不变。
5. 新旧checkpoint的参数映射显式检查，再做有限动作输出检查与端到端时延测量。

研究上的继续条件是：A2相对A1在需要历史的条件中改善，且memory内容干预与错误分析支持它使用了正确过去信息；A3进一步解决latest-state无法区分的顺序／事件问题；A4只有在同信息条件下仍有收益时才进入最终方案。若真实感知差而oracle明显改善，先解决感知；若所有历史模型都无收益，先核查任务是否确实需要历史和模型是否利用记忆，不宜继续堆reader。

**建议的贡献表述**

可研究的主张是：“在不使用高层VLM和额外世界系几何的对象记忆分支中，以固定token预算保留实例级交互状态变化，使轻量扩散策略能区分最新场景相似但操作进度不同的情形，并在遮挡与对象切换条件下改善完整任务表现。”这是一条待证伪假设，不是当前已获得的结论，也不是已完成全面新颖性查重的首创声明。

如果最终只有A2有收益，可以交付实用系统改进，但不应包装成强时序机制创新。如果A3优于latest-state、全景历史及等容量控制，且对顺序、重试和观测频率变化有稳定改善，才有较清晰的研究故事。A4不必为了命名而加入；无VLM、低参数、同感知协议应作为明确实验约束与成本优势，通过测量支持。
