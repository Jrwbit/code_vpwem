## 后续公开故障码检索

用户要求继续搜索后，查到以下厂家原始资料，作为排查方向补充；现场驱动器厂家型号仍未确认，不能将其他厂商表格直接视为现场硬件的最终诊断。

- [珞石 SDK 0.7.x AR C++ 错误码说明](https://docs.rokae.com/docs/SDK--0-7-x-AR/cpp/cpp_error/)明确将 `-514` 定义为上下电失败，处理项包括恢复急停和清除伺服报警。这补充了此前仅将其视为通用上下电失败的说明。
- [心流官方 CANopen 手册 A.23](https://www.flowservo.com/wp-content/uploads/2024/05/%E5%BF%83%E6%B5%81%E4%BC%BA%E6%9C%8D_CANOPEN%E6%89%8B%E5%86%8C_A.23.pdf)，手册第 43、59、126 页：`0x3110` 为用户设定阈值的过压保护；该产品的母线电压读取对象为 `0x6079`，用户过压阈值为 `0x2018:01`，硬件过压上限为 `0x2018:03`。这些对象地址只适用于确认匹配该手册的驱动器，未向现场控制器发送未经验证的寄存器请求或修改阈值。
- [Beckhoff AX8820 官方诊断](https://infosys.beckhoff.com/content/1033/ax8820_diags/19112985099.html)也将该错误码定义为输入电源过压，要求检查输入电压；该产品的电压容差不应用到现场未知驱动器。

因此，下一步可以明确优先排查 **过电压相关保护**，而不是继续调整头部复位速度。应先匹配驱动器型号，读取实际输入／母线电压及对应保护阈值，以区分实际电压过高、阈值设置不匹配或历史过压锁存；现有资料不能证明现场具体是哪一种。排除原因后再清警，并在现场监护下验证是否重现及能否上电。本轮仅检索与读取本机缓存，未清警、上电、调整保护值或启动运动。
