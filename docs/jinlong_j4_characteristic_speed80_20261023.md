# 2026-10-23 J4失电特性更正与左臂80%独立参数实现

用户最新明确：“下电一定不保持，这个是正常的情况，已经清楚了”。据此撤回上一轮“先维修J4至下电保持，再推进80%速度”的前提。腰J4按已知失电不保持特性处理；历史位置变化、报错和软件锁存记录保留，不继续将失电位移本身判为机械损坏。

**左臂80%的独立指令参数已实现并提交统一源码`a7adb17`，通过离线验证；尚未部署或在实机启用。** 用户要的是80%运行，不是仅把页面数值改成80；本轮没有把参数支持写成实际速度验收。

## 已实现的速度参数

| 阶段／层级 | 新行为 | 保留的边界 |
| --- | --- | --- |
| 配置／页面 | 独立`trajectory_joint_speed_percent`，0.1至100%；提供只含80的配置补丁 | 原`trajectory_speed_mm_s`仍表示mm/s；旧配置没有新字段时行为不变 |
| 规划 | 中转、接近及常规返回使用请求比例80%；`insert`及其对应撤离段不超过20% | 原末端指令30／20 mm/s、几何和碰撞复核不变 |
| 预览与执行 | 单段和完整任务都绑定计划中的百分比及mm/s；修改配置使旧路径确认失效 | 显式比例与旧缺省模式混合的整任务拒绝；腰／右臂／单次动作／标定／MoveL未开放新比例 |

保持插入及对应撤离段低速是本轮实现选择，避免把高比例同步用于配合区。没有将所有部件改为80%，没有把原1.0／1.2 rad/s应用保护改成未知的“机械最大速度”。

配置补丁位于统一源码`vision/config/rokae_joint_speed_80.patch.json`，只包含`trajectory_joint_speed_percent: 80.0`；不覆盖任何现场mm/s、标定、工装或坐标配置。它尚未写入现场活动配置。

## J4正常特性对自动检测的影响

当前自动路线把腰部作为下电的非目标部件，同时要求腰角不变。这一假设不适合已确认的失电不保持特性。正确的正常运行方式应是由HMI同一执行所有者建立腰部伺服保持，再覆盖左臂去程、检测停留和返程；持续监测实际腰姿与电源状态。

现有示教保持会话已有上电和监测原语，但会占用执行所有权，不能先按保持按钮，再让另一执行进程启动自动路线。完整适配需同时修改原生会话、MotionManager生命周期和PlanRunner完成状态：左臂路线完成但腰部仍保持时，不能释放所有者或标记为“全部下电安全退出”。

正常下电后应重新读取实际腰姿，后续规划重新绑定基座和视觉关系；不能继续用下电前姿态作为固定基座。历史`SAFE_EXIT_UNCONFIRMED`说明当时退出未满足既有程序判据，不构成“抱闸损坏”诊断。更正设备特性也不意味着自动清锁、忽略非指令运动或跳过原有检查。

本次没有改动上述腰部会话、停机或急停逻辑。因此自动持腰仍是需要实现和验证的软件集成项，不再是要求用户维修J4的前提。
