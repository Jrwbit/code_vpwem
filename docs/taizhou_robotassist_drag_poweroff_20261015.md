# 2026-10-15 RobotAssist 左臂拖动数秒后下电：复现、修复与现场验证

## 结论

本轮复现的直接触发因素是网页控制服务每五秒创建新 SDK 连接做诊断，打断了 RobotAssist 发起的左臂拖动。网页服务内部 `busy=false` 不能证明外部示教器没有控制机器人。原有进程内 SDK 协调锁只协调网页自己的动作，没有覆盖 RobotAssist。

控制仓库修复提交为 `cfd6d95ee6b98dcd9f4304e015f86f18942f95a8`，已更新工控机原服务。普通运行环境下通过 RobotAssist 开启拖动后，连续采集约 65 秒、318 个样本，全部保持左臂 `on/manual/drag`；诊断缓存年龄同步增长，没有周期性重连。测试结束主动关闭拖动，左右臂及腰部均确认下电、手动、空闲。

这次验证的是软件拖动模式持续保持及退出，不是手动引导整条路线、拖动力矩或负载辨识的验收。

## 对照实验

在 RobotAssist 连接左臂 `192.168.71.161`、用户确认现场清空且有人监护后，先确认没有网页运动／回放／采集任务，各部件反馈新鲜、停稳、手动。原有跨进程 SDK 锁用于暂时排除诊断连接，没有删除或绕过锁。

1. 取得 SDK 锁后，在原 RobotAssist 界面开启拖动。约 0.5 秒后左臂进入 `on/manual/drag`，排除诊断期间保持约 18 秒；右臂和腰部保持下电空闲，没有执行点动。
2. 释放该锁，恢复原有正常诊断。约 3.5 秒后左臂从 `on/manual/drag` 变为 `on/manual/idle`，随后约 0.15 秒变为 `off/manual/idle`。这段期间没有点击关闭拖动。
3. 原始对照记录为 118 个排除诊断样本及 78 个恢复诊断样本；前一组最初三个样本仍在开启过渡阶段，其后全部保持拖动；后一组明确记录了拖动退出和下电。

这与代码中后台每五秒 `refresh()`、无条件调用 `backend.inspect()` 的路径相符。原生 `--inspect` 虽不显式调用上下电或拖动命令，但创建 SDK 连接仍能影响控制器状态，不能视为与其他控制会话无关的被动读取。本轮没有进一步声称已追踪到闭源 SDK 内部的某一条具体命令。

## 修改

- 后台只在尚未取得控制器限位时进行初始化；一次成功后使用限位缓存，并保留真实缓存年龄，停止周期性创建 SDK 连接。这样也避开了外部刚按下拖动、反馈尚未更新的过渡窗口。
- 后台初始化及前台显式检查取得协调锁后，都先通过既有反馈流确认整机新鲜、停稳、下电、手动、空闲。外部上电保持、拖动、点动、自动模式或状态过期时不建立诊断连接。
- 网页实际动作仍有新的执行前检查和原生保护；状态流、停止、心跳、控制器限位及报警保护均保留。没有延长拖动退出保护、忽略报警或修改关节限位来掩盖问题。

新增检查覆盖：三部件的外部上电／拖动／点动／自动／运动及过期状态不触发重连、跳过检查时缓存及年龄保持、等待协调锁后重新核对现场状态、成功取得限位后多个后台周期不再重连。
