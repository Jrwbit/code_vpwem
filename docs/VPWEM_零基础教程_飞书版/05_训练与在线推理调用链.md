# 05 训练与在线推理调用链

## 1. 训练入口不是模型本身

以 `pipelines/longmemdpptp_mikasa_image.py` 为例，入口依次做：

```text
读取 Hydra YAML
 -> 创建 Dataset/DataLoader
 -> 创建 condition、memory、diffusion 三个子网
 -> 包成 LongMemDDPM
 -> 循环取 batch 并调用 agent.update(...)
```

查问题时先定位属于哪一层：数据字段错看 Dataset，维度错看三网接口，loss 错看 LongMemDDPM，参数没生效看 YAML 到构造函数的传递。

## 2. Dataset 如何切一个样本

一条完整 episode 会围绕当前训练位置分成：

```text
更早历史：obs[*_mem]                 -> memory
最近 To 帧：obs[普通 key] 的前 To 帧 -> condition
Ta 步动作：action                    -> x0
历史位置：ep_step                    -> 位置编码
```

不同样本的 `Th` 不同，`dynamic_batch_collate_fn` 会在 batch 内补齐。数据集负责选帧，不负责把历史压成 Tm 个 token。

## 3. Pipeline 交给 update 的四件东西

```python
update_log = agent.update(
    naction,       # [B,Ta,A]，归一化动作
    condition,     # 最近 To 帧的多模态 dict 或 [B,To,D]
    memory,        # 更早历史 dict 或 [B,Th,D]
    mem_steps)     # [B,Th]
```

`naction` 先归一化到模型常用范围，推理结果执行前再反归一化。忘记这点会让“数值看着合理”的动作在环境中完全错误。

## 4. `LongMemDDPM.loss` 完整顺序

```text
x0 [B,Ta,A]
 │
 ├─ add_noise -> xt, t, epsilon
 │
condition ── condition encoder ─────────────> [B,To,D]
memory ───── condition encoder ─> [B,Th,D]
                                    │
                                    └─ QFormerMemory -> [B,Tm,D]
 │
 └─ diffusion(xt, t, condition, compressed_memory)
                         │
                         ▼
                  epsilon_hat [B,Ta,A]
                         │
                         ▼
                  MSE(epsilon_hat, epsilon)
```

关键源码位于 `cleandiffuser/diffusion/longmem_ddpm.py:257` 附近：

```python
xt, t, eps = self.add_noise(x0)
condition = model["condition"](condition_input)
memory_tensor = model["condition"](memory)
compressed_memory = model["memory"](memory_tensor, ep_step)
eps_hat = model["diffusion"](xt, t, condition, compressed_memory)
loss = (eps_hat - eps) ** 2
```

默认主基线只需动作去噪 MSE。`memory_aux_coeff` 和 `counterfactual_memory_coeff` 大于 0 时才会额外加损失，它们属于扩展实验。

## 5. `update` 比 `loss` 多做什么

```python
total_loss.backward()
clip_grad_norm_(...)
optimizer.step()
optimizer.zero_grad()
ema_update()
```

EMA 是参数的指数滑动平均副本。训练更新 `model`，评估通常使用更稳定的 `model_ema`。加载、reset 和干预时要知道当前操作的是哪一份。

## 6. 为什么训练与推理的历史处理看起来不同

训练数据已经知道整段过去，所以 `QFormerMemory.forward` 每个样本先 reset，再重放 `Th` 帧。

在线 rollout 不能看到未来，每次只增量收到新观测：

```text
第 1 次 sample：建立最近 To 帧 working memory
第 2 次 sample：新帧进入；滑出窗口的旧帧送进 memory.inference
第 3 次 sample：继续保留 cache 并更新
episode reset：清空所有 cache
```

这两条路径应产生语义一致的状态，但生命周期不同。

## 7. 在线 cache 的三层状态

```text
LongMemDDPM.condition_cache_list  最近 To 个编码观测
QFormerMemory.condition_cache     稀疏的历史观测证据
QFormerLayer.query_cache          各层过去的摘要
```

`LongMemDDPM.reset_cache()` 只清自己的列表；记忆模块还有独立 `reset()`。评估代码应同时清理 `model`、`model_ema` 的 memory 和 agent cache。

## 8. 一次在线动作生成

1. 编码当前新观测。
2. 更新 working-memory 列表。
3. 将滑出的旧 token 交给 `memory.inference`，按采样间隔写入。
4. 得到 `[B,Tm,D]` 历史摘要。
5. 从 `[B,Ta,A]` 随机噪声开始。
6. 重复 `sample_steps` 次调用动作 Transformer 去噪。
7. 从生成序列中切出要执行的 `inference_action_steps`。
8. 反归一化后交给环境。

## 9. dropout 为什么分短期和长期

```yaml
short_cond_dropout: 0.3
long_cond_dropout: 0.3
```

训练时随机丢近期条件或长期条件，避免模型只依赖其中一路，也为某些 classifier-free guidance 设计留接口。但判断模型是否真的用历史，不能只看 dropout；应做 zero/shuffle memory 干预并观察动作或成功率变化。

## 10. 最小调试日志应该打印什么

第一次 batch 建议打印一次：

```python
print("action", naction.shape, naction.min().item(), naction.max().item())
print("condition", condition.shape)
print("history", memory_tensor.shape)
print("compressed", compressed_memory.shape)
print("pred", eps_hat.shape)
```

还要检查：所有 tensor 是否同 device、dtype 是否兼容、是否含 NaN、episode reset 后 cache 是否为空。

## 11. 本章自测

1. Dataset 与 QFormer 谁负责历史选帧？Dataset 选帧，QFormer 压缩。
2. 为什么训练每样本 reset，而 rollout 不每步 reset？训练重放独立样本；rollout 要跨步保留同一 episode 状态。
3. 推理为什么使用 EMA？滑动平均权重通常更稳定。
4. 动作送环境前少了哪一步会出大问题？反归一化。
5. 仅 `agent.reset_cache()` 足够吗？不一定，还需重置实际使用的 memory 模块。
