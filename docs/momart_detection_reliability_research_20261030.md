# MoMaRT：其他检测方案为何可靠，以及可借鉴的做法

日期：2026-10-30。飞书：https://feishu.cn/docx/XgUFdxiLboh4JFxOuZXcufgunZc

**结论：可以借鉴，优先借鉴领域标注与检测器训练、可靠初始化后的因果跟踪，以及部件专门建模。没有证据说明直接换成某个通用模型，就能让目前90×120输入上的六类对象达到95%。** 本轮查阅作者论文和官方代码，并在GPU5完成同一36帧的实际对照；没有重启全量预处理或A1训练，也没有修改策略主干和原始缓存。

## 1. 其他方法实际依赖什么

| 方案 | 原论文/官方实现中的条件 | 可以借鉴什么 | 不能直接推导什么 |
|---|---|---|---|
| BBox-DP / Label-UMI | 激光点提供目标提示，SAM2传播标注，再训练部署用YOLO；策略训练还加入漏框/错框增强 | 先做本场景标注，再训练轻量检测器；保留检测误差鲁棒性实验 | 其任务成功率不等于六类别检测precision；其标注硬件不在我们现有数据中 |
| VIMA | 用环境内数据微调Mask R-CNN，选择时偏高recall，并对策略做额外对象增强 | 仿真场景同样需要领域适配；按episode划分检测数据 | 它不使用预测对象名称，不能证明我们需要的把手类别识别可靠 |
| Scene Graph | 附录错误/时延分析描述首帧Grounded-SAM初始化、XMem跟踪；64次真实实验有4次分割失败 | 避免每帧六份重检测；可靠初始化后传播，丢失时重新检测 | 不是逐框precision/recall≥95%的证据；首次不可见对象仍需后来初始化 |
| YOLO-World | 支持用户词表重参数化和领域微调，官方提供自定义数据训练与移除推理文本编码器的路径 | 六类固定词表可做一次图像前向，或训练固定类别检测器 | 零样本支持某个词，不等于认识我们仿真里的小把手 |
| VLPart | 联合部件级、对象级和图像级数据学习，利用对象间对应关系识别部件 | 将handle当成需要部件监督的目标，定义父对象与部件关系 | 整体物体检测能力不能直接替代部件定位能力 |

来源：[BBox-DP方法3.1–3.3节](https://arxiv.org/html/2602.11885v2)、[VIMA附录C.4与D](https://proceedings.mlr.press/v202/jiang23b/jiang23b.pdf)、[Scene Graph错误与时延分析](https://arxiv.org/html/2606.01072v1)、[YOLO-World官方说明](https://github.com/AILab-CVC/YOLO-World)、[官方微调指南](https://github.com/AILab-CVC/YOLO-World/blob/master/docs/finetuning.md)、[VLPart官方说明](https://github.com/facebookresearch/VLPart)。

VIMA的领域检测训练包含22,741张图和61,822条标注，说明它并非将开箱即用检测器直接接入策略。该规模是原论文设置，不是我们必须复制的标注预算。

Scene Graph正文描述与附录运行频率口径并不完全一致，不能把一次初始化当作所有环境、所有版本的完整部署事实。本报告只将其附录的初始化—传播方式作为可验证设计参考；没有复现第三方论文的精度或速度。

SAM2官方提供多对象提示、纠正和视频掩码传播接口。它适合辅助标注及跟踪，但如果初始框把碗标成把手，SAM2可能持续跟踪这个碗。**分割边界准确与类别语义正确是两个问题。** 离线标注可用完整视频辅助生成标签并人工核验；策略输入缓存仍只能使用当前与过去观测，不能拿双向传播/未来帧修正后的特征冒充在线感知。

来源：[SAM2官方视频接口](https://github.com/facebookresearch/sam2#video-prediction)。

## 2. 对照当前错误：为什么调提示词还不够

GroundingDINO官方说明：输出框对输入文本的各token有分数；默认box_threshold筛选使用最高token分数，返回短语再由text_threshold决定；支持用句点分隔多个类别，并提供明确token span的短语打分。提示词不等于检测器最终确认的类别。

来源：[官方输入输出说明](https://github.com/IDEA-Research/GroundingDINO#star-explanationstips-for-grounding-dino-inputs-and-outputs)、[官方given-phrase推理代码](https://github.com/IDEA-Research/GroundingDINO/blob/main/demo/inference_on_a_image.py)。

我们旧实现把提示词序号直接当class_id，确实应修正。但帧10133原始输出已经把红碗完整命名为`a dishwasher door handle`，score约0.610，所以完整短语核验也不能修复这个语义错误，提高阈值同样不能保证正确。

原图仅90×120。放大到600×800会增加计算，不会恢复原本没有的小部件像素。是否能取得更高分辨率原始图、是否允许重渲染，需要另外核验；本轮没有假定这类数据可用。父对象ROI可以减少无关背景，但前提是父对象先定位可靠，不能把父框错误变成对子框的错误约束，也不能恢复丢失的图像细节。

## 3. 已执行：同一36帧的三路对照

使用上次审计固定的36帧：首个数据集前20608帧、seed20261030、无放回随机抽样。它们已暴露过错误，所以现在属于开发集，不能再充当独立验收集。模型与revision保持不变，仍为`IDEA-Research/grounding-dino-tiny`、`a2bb814dd30d776dcf7e30523b00659f4f141c71`，FP32、相同600短边、0.25阈值、0.5类内NMS、红碗颜色门及最大8框规则。

三路分别为：原六提示；六提示并严格核验返回短语；同一图像配六类联合caption，以明确token span平均概率打分。后两路仅为独立探针，未替换生产感知。联合短语均分与原最高token分数口径不同，阈值相同只是开发对照，不是等precision或等recall实验；耗时变化也不只来自图像份数。

| 红碗输出数 | 22 | 22 | 22 |
| 洗碗机门输出数 | 38 | 35 | 2 |

计时为36帧中剔除首帧后的35帧，在GPU5、torch CPU线程4下实测；包含processor、同步GPU检测及框筛选，不含ROI特征、跟踪、memory、策略或磁盘。两种模式同一进程按帧先六提示再联合提示，未随机交错；这里只说明该小样本条件下约4.85倍检测加速，不能外推整套系统吞吐。

原六提示重跑与缓存36/36帧的框数、类别及坐标在1e-4容差内一致。严格核验后剩余28个洗碗机把手框均可对应到上轮已目视判错的33框，没有纠正对象位置。联合提示的唯一把手输出在帧20157，目视仍覆盖机械臂。这些是助手目视检查及记录匹配，不是独立人工GT。**输出减少不等于precision提高，零输出也可能是全部漏检；当前没有GT，不能报告召回率、mAP或达到95%。** 红碗输出数量一致也不代表框定位质量完全相同。

## 4. 建议借鉴到本项目的具体路线

1. 先固定类别和GT标准。洗碗机、门、门把手、篮架、抽屉、抽屉把手的包含关系需要明确；标注可见区域、遮挡状态及同类实例。遮挡不可定位时允许缺失，不填整幅图，不把历史框算作当前检测。
2. 从不同任务、不同episode及阶段抽取场景内样本，特别覆盖开门、抽屉变化、机械臂遮挡、小把手和无目标负例。按episode划分train/dev/test，避免相邻帧跨集合。SAM2辅助传播后核查身份、边界和遮挡；不能将当前错误缓存直接当作可信训练标签。
3. 用这些标签微调一个六类别轻量检测器；可比较固定类别YOLO与YOLO-World领域微调。保留目前GroundingDINO为辅助提案，而非未经验收的GT来源。父物体—部件ROI作为可独立验证的候选改进，不先写成必然有效。
4. 对可靠检测做因果跟踪，定期及低置信触发重检测。跟踪与重检测频率先在dev上确定，离线回放和在线调用同一实现；新对象进入视野时可以初始化。跟踪失败须标记不可见，不持续强化错误类别记忆。
5. 独立test按类报告precision、recall、IoU≥0.5/0.75、小对象表现、ID切换和延迟。把“95%”落实为例如每类precision≥95%，同时报告recall及样本量/区间，不能只用整体precision掩盖把手类失败。是否同时要求recall≥95%应单列，因为它与precision是不同验收条件。

先前红碗`combined_blend`可作为已验证的专用参考：独立确认集990/995预测命中，即precision约99.50%，可见帧命中率约92.70%。它结合颜色、关联、模板和局部重检测，指标只针对红碗；不能用于宣称六类同等可靠。为避免新的混合协议混淆，若采用它作为六类管线的一部分，必须冻结同一红碗分支并在A1/A2/A3全部复用。

检测器定稿后，A1/A2/A3共用同一检测结果、ROI特征、类别/实例管理、采样时刻和协议版本，只改变历史可读范围。新检测器输出会改变语义和特征分布，原20928帧低质量感知缓存不能混用，应使用新的缓存版本重建。ResNet18及原PTP/DiT主干无需因检测器领域微调而改变；新增部署模型位于外部感知分支。是否加速到目标控制频率仍需端到端实测。
