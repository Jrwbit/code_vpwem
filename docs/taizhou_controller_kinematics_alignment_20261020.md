# 台州机械臂有效DH、反馈口径核对与规划修正

已于2026-10-20追加至[飞书全流程报告](https://feishu.cn/docx/I2GAdun3nofskUxAOjWcxVwjnJO)，保留原有内容，上传78个动作的反馈口径对照图，并回读核验正文、表格和图像。本次与独立路线报告一起追加，原有65个顶层块的顺序及原正文保持不变。

## 结论与需要更正的解释

1. **原规划使用固定理论DH，控制器的有效DH包含本机补偿，左右臂各不相同。** 已将参数按控制器身份传入正解、末端逆解与碰撞模型，不使用固定XYZ偏置。
2. **必须区分SDK官方正解与SDK笛卡尔状态getter。** 有效DH与控制器官方`calcFk`一致；三轮记录中的`posture(flangeInBase)`却更接近指令关节的有效DH正解，而非反馈关节的有效DH正解。
3. 因此前面把“名义模型与同快照SDK笛卡尔位姿差约1.39 mm”完整称为纯模型差异并不严谨。该比较混合了模型参数差与关节/笛卡尔反馈口径。此次用相同关节分别比较理论与有效模型，才分离出纯模型差异。
4. 修正后的离线完整路线通过碰撞检查；现场代码已经使用有效DH。**约0.8 mm量级的关节到位残差、手眼及工具的实物绝对精度，未在本次被消除或验收。**

## 读取与定义核对

设备仍为物理左臂`.161 / AR5-5_0.8L-W4C5C11`、右臂`.160 / AR5-5_0.8R-W4C5C11`。七轴反馈与URDF关节名逐轴对应，弧度输入，没有额外施加手臂零位偏移。腰部J2的控制器/模型90°偏置保持既有定义。

SDK 0.7.1本地官方头文件`robot.h`提供`getRobotCfg_DHparam(bool)`：`true`读取标称参数，`false`读取优化后或设置后的参数；每轴按Alpha[°]、A[mm]、D[mm]、Theta[°]排列。按八行修改DH重建，前七行含关节角，第八行为固定法兰。

没有新建并行诊断控制客户端。先在现有原生状态采集程序中加入一次性getter，再在三部件下电、手动、空闲及运动互斥锁下，受控更新并重连原采集进程，读取双臂各自的标称/有效DH、SDK基座设置和工具工件设置。诊断读取失败独立记录，不据此重连健康反馈。

官方正解使用`Robot_T<collaborative,7>::model()`的控制器通路，不使用支持机型列表未包含AR5的xMate本地模型库。指定单位工具工件，并通过SDK基座变换将结果转换回`flangeInBase`，避免把外部参考系位姿误当法兰基座位姿。

双臂各取当前关节、零位和三组不要求实机到位的数值输入，共10组计算查询，没有令机器人移动到这些姿态。独立有效DH正解、修正后的MuJoCo法兰与官方正解的最大差均小于`0.001 mm / 0.001°`；实际数值约为`3.32e-7 mm / 3.34e-8°`，只是计算与序列化精度，不是物理精度。

这些对照未发现当前机型、关节顺序、正方向、角度单位或法兰基座定义有不一致。整机腰部/安装几何仍使用名义URDF，没有通过独立计量验收。

## 三轮78个动作的反馈口径复核

按原始记录中实际观察到的活动operation_id关联最终停稳样本，不用计划游标代替动作身份。排除记录开始前上一条回执后，共78个动作。

| 同一停稳样本的比较 | 位置差范围 mm | 位置差中位数 mm |
| --- | --- | --- |
| 相同反馈关节：有效DH vs 理论DH | 0.9271–1.9060 | 1.4860 |
| 理论DH(反馈关节) vs SDK笛卡尔getter | 0.7835–2.0885 | 1.4971 |
| 有效DH(反馈关节) vs SDK笛卡尔getter | 0.1964–0.8238 | 0.5682 |
| 有效DH(指令关节) vs SDK笛卡尔getter | 0.00050–0.00798 | 0.00217 |
| 有效DH(反馈关节) vs 有效DH(指令关节) | 0.1956–0.8225 | 0.5701 |

最后两行的明显区别支持：本次SDK笛卡尔getter与指令/参考通道高度一致，不适合作为实际反馈关节的独立正解真值。不能据此直接断言控制器内部实现、物理位置或传动侧测量定义，仍需厂家明确接口语义。

三轮检测位的J1反馈相对指令稳定相差约0.07°。例如第一轮检测位，有效DH的反馈关节与SDK笛卡尔getter差约0.8122 mm，而指令关节与该getter仅差约0.0069 mm。因此先前根据SDK笛卡尔getter得到的高重复性，不能代替实际到位准确度验收。

## 已实现的修正

控制与检测源码仓库：`/home/wjr/code/jinlong-motor-arm-control`。

- `controller_kinematics.py`按控制器ID和机型验证每臂有效DH，拒绝错误身份、非有限数值和不完整模型；参数只进入运行快照，不把本机补偿表硬编码或提交Git。
- `FrameModel`、示教末端逆解、完整路线使用同一份有效DH。历史离线输入无控制器参数时保留明确的名义模型来源；存在损坏的有效参数时拒绝，而非静默回退。
- MuJoCo不仅修正末端目标，也同步修正两臂各连杆的关节原点、关节轴及附着碰撞几何，保持各网格与名义DH连杆的安装关系。双臂10组位姿已与官方正解逐组比较。
- 路线输入/回执保存运动学摘要。规划装载及执行前核对当前摘要；参数改变或旧路线缺少对应摘要时，要求重新规划。复用路线的离线校验工具也采用同一碰撞模型，并检查运动学来源。
- 独立审计工具支持运行快照中的有效DH；独立数值逆解和正解仍不调用生产求解器。

理论DH与有效DH之间的差随姿态变化，本次不修改手眼矩阵、TCP、工装高度、工作腰姿、关节目标结束容差或验收勾选项。
