## 官方接口及现场SDK静态验证

官方v0.7.1头文件将`MoveAbsJCommand.jointSpeed`定义为0至1的比例，非负时生效，负值才使用`speed`折算。[官方数据结构](https://raw.githubusercontent.com/RokaeRobot/xCoreSDK-CPP/v0.7.1/include/rokae/data_types.h)。

在现场已安装的`/home/bit-bhr/sdk/xcore-0.7.1/Release/linux`内，仅构造`MoveAbsJCommand([0]*7,30.0,0.0)`数据对象：初始`jointSpeed=-1.0`，赋值0.8后读回0.8，`speed`仍为30.0，断言通过。未创建Robot实例或连接控制器。因此该验证证明接口参数可表达80%，不证明控制器接受执行或实际达到80%运行速度。

SDK另有`adjustSpeedOnline`，其范围0.01至1是对原路径速度的倍率，当前原生路线发送1.0。将其设0.8只会把原路径再乘80%，不能代替本次提速目标。官方`speed`折算表的500至800 mm/s为80%档位，仅是该折算机制的说明，本次没有据此给实机下发500至800 mm/s。[官方方法说明](https://docs.rokae.com/en/docs/SDK--0-7-x-AR/cpp/cpp_method/)。

项目2026-10-16历史记录中，单独改变`jointSpeed`的1%与20%未体现预期速度差，改变末端速度字段才出现变化；记录位于统一源码`arm_control/tools/README.md`及`native/xcore_motion.cpp`。该现象仍需解释，不能直接认定为已经解决的固件问题。公开接口说明与现场效果存在待核对项，故不能只把数值80写入旧字段就宣称任务完成。
