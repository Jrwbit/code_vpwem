# BHR 近期实验与对照缺口盘点

> 快照时间：2026-09-20 12:15 CST  
> 范围：`bhr-server` 上 2026-09-07 至 2026-09-20 有训练、checkpoint 或评测写入的 VPWEM 相关实验。  
> 判定原则：只有在同任务、同训练预算、同输入表示、同评测 episode 和有效 evaluator 下得到的结果，才标记为完整对照。

## 一、总结论

最近两周 BHR 上主要跑了 8 类工作：ShellGameTouch 四方法公平历史实验、MoMaRT 多任务 400k/1M、MoMaRT embedding 公平历史、Robomimic strict No-History/Direct-History、Direct-History 400k 初筛、MIKASA 单任务 Direct-History、MIKASA-All 多任务、real-batch 可行性测试。

目前没有一组新实验同时满足“四方法齐全 + 输入架构匹配 + evaluator 有效 + 多 seed”。最接近闭环的是 ShellGameTouch，但 BHR 上 VPWEM 评测有 reset bug，必须在服务器用修复后入口复评。

## 三、已有结果的解读

### 3.1 ShellGameTouch 600k

BHR 上原始结果为 Direct 95%、Direct-token2 94%、No-History 88%、VPWEM 29%。VPWEM 分支在 episode reset 后没有清空 online/EMA Q-Former memory，后续 episode 继承了前一批的记忆和时间位置。本地在其他条件不变时仅修复 reset，VPWEM 得到 92%。这个 92% 是定位 bug 的对照，不能直接写成 BHR 正式成绩。

因此，这组可以说“四方法训练齐全，并且已定位评测 bug”，但还不能说“四方法正式对照完成”。

### 3.2 MoMaRT 400k 和 1M

400k 三方法结果已齐，Direct-token2 的宏平均最高；1M 中 Direct-token2 为 71.67%，VPWEM 为 65.33%。但 VPWEM 使用 embedding policy 及任务 context encoder，Direct/Direct-token2 使用 raw visual policy。这些数字可以做系统层定位，不能归因为 memory 结构的严格胜负。

1M No-History checkpoint 已经存在，但当前 1M evaluator 脚本的 method queue 只有 `vpwem/direct/direct_token2`，没有 `no_history`。这是明确的评测缺口，不需要重训 No-History。

### 3.3 Robomimic strict

No-History 四任务已训练到 1M，但没有在线成功率。Direct-History 四任务在 2026-09-14 停止：Square/ph 948k、Square/mh 934k、Transport/ph 456k、Transport/mh 441k；也没有任何 strict 在线评测结果。因此，即使历史 VPWEM strict 1M 参考值已存在，这轮新实验仍然没有形成 No-History / Direct-History / VPWEM 三方在线对照。

## 四、没有跑齐的对照实验

### P0：利用现有 checkpoint 即可补齐

1. **ShellGameTouch VPWEM 600k 服务器复评**：使用修复后 memory reset，与 Direct、Direct-token2、No-History 相同 100 episodes 和 seed 重跑。
2. **MoMaRT No-History 1M 评测**：10 个任务配置×30 episodes，与已有 VPWEM/Direct-token2 结果共用评测 seed。
3. **MoMaRT No-History 400k 评测**：当前 400k 表只有 VPWEM、Direct、Direct-token2，缺“不用历史”下界。
4. **Robomimic No-History strict 1M 在线评测**：Square/ph、Square/mh、Transport/ph、Transport/mh，使用 VPWEM strict 的固定 episode 列表。
5. **Robomimic Direct-History strict 现有 checkpoint 评测**：先评 Square 900k 以及 Transport 400k，再决定是否恢复到 1M；不应让现有 checkpoint 继续只有 loss 而无 success。
6. **Direct-History RememberColor3 600k 收尾评测**：当前训练已到 600k，但最新评测仅到 400k。
7. **Direct-History RememberColor5/ShellGameTouch 400k 评测**：已有 400k checkpoint，但这一轮目录没有结果文件。

### P0：需要续训或重训才能补齐

8. **MoMaRT Direct 1M 收尾及评测**：快照时为 968k/1M，完成后跑同一套 10×30 评测。
9. **MoMaRT embedding 三个对照方法**：Direct、Direct-token2、No-History 当前都在 step 0 退出；必须与已完成的 embedding VPWEM 使用同 encoder、effective batch、step 预算重跑，否则 MoMaRT 只有跨架构对比。
10. **Robomimic Direct-History strict 未完成部分**：Square 还差约 5–7%，Transport 还差约 54–56%。是否续训应由现有 checkpoint 在线评测决定。
11. **MIKASA-All original-vs-embedding DP-PTP**：original 到 600k 后，当前队列才会构建 embedding 并训 embedding DP-PTP；两者还需同 seed/episode 评测。
12. **MIKASA-All 四方法对照**：当前另一条 Direct-token2 BS256 刚启动，但还没有同协议的 No-History、Direct 和 VPWEM 多任务训练/评测矩阵。

### P1：已有方法对比，但缺少能支撑论文归因的对照

13. **Token-matched Direct-History-2tok**：当前 Direct-History 有132/260个历史 token，VPWEM 只有2个；没有这组不能将差异归因为 Q-Former 压缩。
14. **同 history timestamp / 同 sampler 对照**：Direct 的 anchor+recent3 与 VPWEM 的 stride20+FIFO8 时间覆盖不同。
15. **历史组成消融**：No-History、anchor-only、recent-only、anchor+recent、VPWEM。
16. **因果 memory intervention**：correct history、zero history、shuffle history、matched-wrong history/random donor。ShellGameTouch 尤其需要在修复 evaluator 后做这组。
17. **多训练 seed**：最近新实验基本都只有 seed100；至少还缺 seed200/300 及配对置信区间。
18. **Checkpoint-matched 曲线**：400k 方法不应只和 VPWEM 1M 比；需在相同 400k/600k/800k/1M 节点评测。
19. **效率对照**：同时报告参数量、历史 token 数、峰值显存、训练吞吐、单步推理时间；目前只有部分评测的 inference time。

## 六、最小闭环顺序

1. 先不重训：补 ShellGameTouch VPWEM 服务器复评、MoMaRT No-History 400k/1M、Robomimic No-History strict 1M、Direct strict 现有 checkpoint 评测。
2. 收尾已接近完成的 MoMaRT Direct 1M，随后跑 10×30 评测。
3. 根据 Direct strict 现有 checkpoint 的 success 决定是否续训，避免先消耗数天再发现无效。
4. 若要写“memory 结构公平比较”，再补 MoMaRT embedding 三对照和 token-matched Direct-2tok。
5. 单 seed 有明确正向结果后，最后扩 seed200/300 和因果干预。
