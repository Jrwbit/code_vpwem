# MoMaRT No-History 与带框架构入门及修改指南

日期：2026-10-28。适用对象：希望从零理解模型、找到代码修改位置、并能在面试中解释设计的读者。这里的“带框”专指 Boxed No-History，在主 RGB 上画红框的版本；“画框＋坐标/ROI token”属于另一项实验。

## 读完应该能做到什么

你应该能闭卷画出从传感器到动作执行的流程；说清每个模块接收什么、输出什么、为何存在；区分训练和部署；面对失败知道先查哪一环；为一个修改提出可验证的实验。背出 ResNet 和 Transformer 的名字，只完成了第一小步。

推荐分三遍阅读：第一遍只看故事和总图；第二遍跟着张量和代码入口走；第三遍回答末尾问题，再设计一次单变量实验。

## 先跟机器人走一遍

设想机器人要把一个红碗放进洗碗机。它首先需要知道“现在在哪、红碗在哪、手离红碗多远、这次要做什么”，然后决定接下来怎样移动。

普通 No-History 读取最近两次传感器观测。视觉网络压缩图像，其他编码器处理距离扫描和机器人自身状态，再把这些信息拼成两份数字摘要。任务编号补充“当前要完成哪种任务”。动作模型以这些摘要为条件，从随机噪声逐步生成一小段动作，执行其中一部分，然后重新看环境。

带框版在主相机图像上多做一步：把目标位置画成红色矩形，帮助视觉网络注意目标。之后仍然经过同一套观测编码和动作生成流程。红框不会直接告诉机器人应如何抓取；从像素到动作的映射仍由策略学习。

No-History 的意思是“不使用长期记忆分支”，不是“只看当前一张图”。它保留最近两帧，因此有短时间变化信息；更早发生过什么，没有专门缓存供策略读取。

## 总图和两种方法的边界

![No-History 从最近观测到滚动动作执行](../artifacts/momart_main_figures_20261028/native_no_history.png)

![带框版在主 RGB 输入前加入目标提示](../artifacts/momart_main_figures_20261028/native_boxed.png)

两张图的共同主线是：最近两帧多模态观测 → 每帧一个 256 维摘要 → 加任务嵌入 → 条件动作扩散 → 预测 9 个动作位置 → 取索引 1 到 8 执行 → 重观测。

带框版额外主线是：训练时离线框／部署时在线框 → 在主 RGB 画红色轮廓 → 进入原有视觉编码器。

| 关键问题 | 普通 No-History | Boxed No-History |
|---|---|---|
| 主相机 RGB | 原图 | 原图加 1 像素红框，无有效框时保留原图 |
| 腕部图像、两路深度、scan、自身状态 | 读取 | 同样读取，不在这些输入上画框 |
| 最近观测 | 2 帧 | 2 帧 |
| 长期记忆 token | 0 | 0 |
| 动作骨干 | PTP Transformer 加 DDPM | 同类骨干 |
| 策略显式接收框坐标吗 | 否 | 否，坐标用于画像素 |
| 检测器随动作损失一起训练吗 | 无此分支 | 当前链路不是检测器与策略端到端联合训练 |

图中的“骨干”是主要计算网络；token 是网络处理的一份向量；embedding 是把某类信息编码为向量。它们不是三种额外传感器。

## 模块逐个拆开

### 数据与时间窗口

训练样本来自演示轨迹，由对齐的传感器观测和动作组成。数据集选取最近两次观测，以及长度为 9 的动作窗口。批量维度 B 表示一次同时处理多少个训练样本。

数据整理必须保证相机、深度、自身状态、动作和框对应正确时刻。画得很准确但错了一帧的框，也可能误导控制。轨迹边界如何补帧、动作如何归一化，应以 dataset 和 normalizer 实现为准；修改窗口长度时不能只改网络参数。

### 目标框生成与画框

当前训练框来自离线 Grounding DINO tiny，文本提示为 `a red bowl.`，保存在 sidecar 中。sidecar 是附在演示数据旁边的框记录，训练取样时按对应帧读取。

在线评测使用冻结的 `combined_blend` 检测／跟踪链路，已记录配置为 `max_age=3`、`refine_alpha=0.5`。检测负责发现目标，跟踪利用时间连续性维持目标位置；具体保留与融合规则应查跟踪实现，不能只凭参数名猜公式。

框用归一化的 `(x1,y1,x2,y2)` 表示，再映射到图像像素，画出红色轮廓。它不裁掉背景，也不新增策略 token。检测器内部出现 `use_roi`，不等于策略网络有 ROI 分支。

这里有一个值得优先研究的问题：训练看离线框，部署看在线跟踪框，两者可能在误检、漏检、抖动和滞后上不同。输入来源不同已经确认；它造成多少成功率损失仍需实验。

### 多模态观测编码

主 RGB、腕部 RGB、主深度、腕部深度分别经视觉编码，当前配置使用 ResNet18。可以把它理解为逐层提取局部纹理、物体形状和空间线索。相同模态的两帧共用编码器参数，不是每个时刻重新学一套网络。

scan 是距离扫描信号，经 ScanCore 处理；proprio 是机器人自身状态，当前为 10 维。RGB 擅长提供外观，深度补充几何距离，scan 提供周围距离信息，自身状态说明机器人当前姿态。是否每种输入都贡献收益，需要消融验证。

各模态特征拼接后，通过 MLP 压到每帧 256 维。MLP 是多层全连接网络；拼接是把不同信息首尾接起来；压缩后的向量是供动作模型使用的摘要，并非可直接解释的 256 个物理量。

当前图像配置为 90×120，训练裁剪为 75×100。裁剪用于训练增强，但可能影响目标和细红框的可见性。检查必须针对真正送入网络的裁剪、归一化后输入，而不只看原始截图。

### 任务嵌入

同一个场景里，“放进洗碗机”和“从洗碗机拿出”可能需要相反动作，所以模型还要知道目标任务。当前使用 5 种语义任务的编号，通过可学习的 embedding 表查出 256 维向量，加到两帧观测摘要上。

这里是向量相加，不是额外添加第三个观测 token，也不是自然语言大模型理解指令。10 个评测配置来自任务与 expert/suboptimal 设置组合，不等于 10 个语义任务嵌入。

### PTP 动作 Transformer

PTP 指 Past Token Prediction。当前动作序列覆盖最近观测窗口对应的较早动作位置与后续待执行位置。长度满足标准训练设置 `9 = 2 + 8 - 1`。第 0 个位置参与序列建模，实际执行从第 1 个位置开始。

Transformer 采用 8 层、4 个注意力头、隐藏维度 256。动作 self-attention 用于建模动作位置之间的关系；cross-attention 让动作位置读取观测条件。每一层不是一个真实机器人动作，也不是一次环境交互。

动作 self-attention 使用因果 mask：动作位置 i 看不到后面的动作位置。cross-attention 另有时间对齐 mask：第 0 个动作位置只能看第一帧；从第 1 个动作位置开始，两帧均可见。所有动作位置都能看扩散时间 token。这限制的是网络内信息访问，不是删除输入图像。

虽然使用因果注意力，DDPM 每轮仍同时更新整段动作张量；不能把它讲成语言模型那样逐个动作采样生成。

### DDPM 扩散生成

扩散可以理解为“学会从被噪声污染的动作里去掉噪声”。训练时，我们知道演示动作，主动加上随机噪声，再让网络根据观测和扩散阶段预测噪声；当前默认是噪声预测目标。

简化训练公式为 `x_k = sqrt(alpha_bar_k) × a + sqrt(1-alpha_bar_k) × epsilon`。a 是归一化演示动作，epsilon 是随机噪声，k 是扩散阶段；基本学习目标是让预测噪声接近 epsilon。实际损失权重和 mask 以训练实现为准。

部署时没有未来真实动作，从噪声开始，按 DDPM 更新规则反复调用 Transformer，当前采样配置为 50 步，最终得到动作序列。50 次去噪不等于机器人执行 50 步；扩散阶段 k 也不是环境时间 t。

扩散能表达多种可能的动作轨迹，适合演示中存在多解的情况；代价是反复计算带来的延迟。本项目是否优于其他动作生成器，需要同条件对照，不能由原理直接宣布。

### 动作恢复与闭环执行

模型输出的是归一化动作，执行前按训练使用的 normalizer 恢复到环境动作尺度。动作维度当前为 10；每一维的物理含义必须查环境动作定义，不能未经核查直接说成十个关节角。

标准方案预测 9 个位置，执行切片 `actions[:,1:9]` 共 8 步，然后获取新观测再规划。这称为滚动执行：既保留短段动作的连续性，也利用下一次观测纠偏。

已有 action4 实验保持 horizon=9、obs_steps=2 和权重不变，只执行 `actions[:,1:5]`。更频繁观察可能减少开环误差，但会增加推理频率，也改变在线 tracker 更新和成功标志检查频率。

## 用形状检查自己是否真的理解

以下省略中间视觉特征维度；B 为批大小，不随示例固定为某个值。

| 位置 | 张量形状或数量 | 含义 |
|---|---|---|
| 每种图像输入 | `[B,2,C,H,W]` | 两帧，C 为该模态通道数 |
| scan | 每帧 `1×100` | 距离扫描输入 |
| proprio | `[B,2,10]` | 两帧自身状态 |
| 观测编码结果 | `[B,2,256]` | 每帧一份融合摘要 |
| 任务嵌入 | `[B,256]`，沿时间广播 | 同一任务加到两帧 |
| 长期 token | 0 个 | `nn_memory=None`、`Tm=0` |
| 条件序列 | `[B,3,256]` | 扩散时间 token 加两帧观测 |
| 带噪动作输入 | `[B,9,10]` | 每个位置 10 维动作 |
| 动作投影 | `[B,9,256]` | 网络内部表示 |
| 噪声预测 | `[B,9,10]` | 和带噪动作同形状 |
| 最终标准执行段 | `[B,8,10]` | 去噪完后切片与反归一化 |

条件序列和动作序列走两条输入路径，通过 cross-attention 交互；不是把它们直接拼成 12 个同类动作 token。

## 训练与部署分别发生什么

| 环节 | 训练 | 在线评测或部署 |
|---|---|---|
| 观测来源 | 演示轨迹采样 | 环境实时反馈 |
| 框来源 | 离线 sidecar | 在线检测和跟踪 |
| 真实动作 | 有，作为监督目标 | 没有，要由模型生成 |
| 噪声 | 给真实动作加噪 | 从随机动作噪声开始 |
| 网络运行 | 学习某个采样扩散阶段的去噪 | 反复去噪得到动作段 |
| 梯度更新 | 更新可训练策略参数 | 不进行策略训练 |
| 执行 | 损失优化不等于真实环境执行 | 执行动作后重观测 |

当前短条件 dropout=0.3，会按样本丢弃短观测条件；它不同于 Transformer 内部 attention dropout，也不同于仅不画红框。No-History 没有长期记忆可补位，因此值得单独比较 0.3、0.1、0，但降低它是否有效是实验问题。

## 下一步修改如何选择

先定位失败阶段，再挑最小改动。以下是建议的实验路径，不是已证实的故障归因。

| 观察到的现象 | 先收集什么证据 | 候选修改 | 怎样验证 |
|---|---|---|---|
| 框错位、跳动、遮挡后跑偏 | 连续帧及在线框，标出关键接触阶段 | 用冻结在线链路顺序回放生成训练框 | 同起点、同预算比较旧框与同源框续训 |
| 目标对了，接近或放置阶段仍偏离 | 动作段执行前后误差及耗时 | 执行段 8 改 4，必要时再测 2 | 同权重评测成功率、耗时、失败阶段 |
| 怀疑依赖红框且无框就失败 | 相同场景的有框、无框和错框输入 | 仅框 dropout 或按实测误差抖框 | 单独训练消融，不同时改短条件 dropout |
| 怀疑没有充分使用观测 | 各任务错误类型与条件消融 | short_cond_dropout 从 0.3 单独降到 0.1 或 0 | 同数据、同预算，比在线任务成功率 |
| 视觉摘要丢失精细空间信息 | 裁剪后输入、目标尺寸、定位失败案例 | 考虑空间 token 或独立 ROI 表征 | 先复查已做 ROI 实验，再设计新对照 |
| 目标消失很久后忘记此前线索 | 任务是否确实依赖两帧以外的信息 | 增加历史窗口或研究长期记忆 | 与增加容量但不加历史的对照区分 |

优先次序建议：整理已有 checkpoint 评测 → 检查框与执行失败案例 → 同源框训练对照 → 短条件 dropout 单变量实验。不要因为模块名“更高级”就直接换更大模型。

一次可审查的实验计划应写清：假设、唯一改动、对照、固定项、主要指标和失败判据。例如“同源框会降低部署输入差异”应从同一 checkpoint 出发，固定后续更新次数、学习率计划、数据和在线评测链路，比较两种训练框；若成功率与关键阶段错误没有改善，就不能宣称假设得到支持。

## 面试回答和追问

**一分钟介绍。** 这个项目研究多模态观测下的机器人动作生成。No-History 保留最近两帧，把图像、深度、距离扫描和自身状态融合成两个 256 维观测 token，并加任务嵌入。PTP Transformer 在观测条件下预测动作噪声，DDPM 经 50 步去噪得到 9 个动作位置，标准执行其中 8 步再重观测。带框版只在主 RGB 上加入目标红框提示，不增加长期记忆和策略坐标 token。当前关键研究点是训练离线框与在线跟踪框的差异，以及动作执行长度与闭环纠错的关系。

**为什么不用单帧？** 两帧提供短时间变化线索，有助于推断相对运动；但能否取得收益仍需单帧对照，两帧也不等于解决长期记忆。

**为什么画框可能有用，也可能有害？** 它给视觉编码器明确的目标位置提示，但错误、滞后或训练部署不一致的框会形成干扰。画框没有赋予策略准确的三维抓取点。

**为什么是 9 个位置却执行 8 步？** 当前 PTP 窗口含一个较早动作位置。两帧观测下执行从索引 1 开始，长度 8；不是漏执行，也不是执行全部 9 个动作。

**两个时间有什么区别？** 环境时间表示机器人与世界推进到哪里；扩散时间表示动作去噪到哪个阶段。一次环境规划内会进行很多次扩散计算。

**self-attention 与 cross-attention 有什么区别？** 前者让动作位置相互读取，后者让动作位置读取观测和扩散时间条件。两个 mask 分别控制动作因果关系与观测时间对齐。

**为什么输出噪声而不是直接输出动作？** 训练目标定义为预测加到动作上的噪声，采样器依据噪声预测更新当前动作估计，最终才得到干净动作。其他预测目标可行，但修改时必须同步采样公式和配置。

**为什么不用训练 loss 决定哪个模型好？** 训练 loss 衡量特定加噪分布上的拟合，机器人成功还取决于闭环误差累积、观测偏移与任务要求。必须做在线任务评测。

**加 ROI token 会不会更好？** 不能保证。已有独立版本 150k 为 53.33%，低于同期画框版 59.33%。它说明这次设置没有显示收益，不证明所有 ROI 设计都无效。

**为什么画框可能有帮助，但把框和位置信息作为观测反而降分，是实现问题吗？** 当前没有发现明确的坐标顺序、归一化或最新帧路由错误，但完整动态验证尚未完成。对象版不只多输入四个坐标，还增加了高频坐标编码和共享 RGB 编码器的 ROI 分支；小幅框抖动、共享梯度、原图坐标与裁剪图像的参考系差异，以及训练离线框与在线框的差异，都值得分别验证。原始坐标 Fourier 编码最高周期在 120 像素宽图上仅约 0.0073 像素，属于具体设计风险，尚不能据此归因 6 个百分点的下降。另外，“画框比不画框好”需要同预算对照，不能用普通版 1M 与画框版 150k 证明。详见 `docs/momart_boxed_token_audit_20261028.md` 及[飞书审计报告](https://feishu.cn/docx/ACTLdfMHCoVVsyxqhNycPrq1nm4)，其中区分了已核查事实、假设和未完成测试。飞书正文及两张表已回读核对，本次无新增图像。

**你下一步会做什么？** 先检查同一批失败轨迹的框与执行误差，再从同一权重、同一预算测试训练框同源化；单独测试条件 dropout。这样能把结果对应到具体假设，而不是同时改很多模块。

**你的贡献是什么？** 按实际完成内容回答：哪些模块由你实现，哪些训练或评测由你运行，哪些是继承基线，哪些结论仍是假设。会解释系统不等于独立实现了所有模块。
